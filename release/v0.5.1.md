# KCoder v0.5.1

> 发布日期：待定 · 上游基线：deepseek-harness 0.1.2-alpha.3 (dd6322d6)

## 变更

- **「带图发送丢图」根因修复：附件插件 @dsh-external/dsh-drag-to-attachment 整线退役**：该插件采用「附件仅引用真实路径」模式——拖入文件落盘后以 `[附件]名称|路径` 文本行随消息发送，与上游原生图片链路（粘贴图片随消息携带真实图片数据直达多模态）在发送事务上叠加，是「带图发送图片丢失/残留输入框」与「发附件后输入框锁死」两类现场的共同根因。本版整线退役：预置清单摘除，历史遗留实体三清自愈（dependencies 声明、bundles 层叠声明、node_modules 实体随启动自动移除）；宿主侧配套一并回收——attach-picker 附件按钮拦截器拆除，跨平台补丁链（rc.8 sendSession 漏 return 致输入框锁死、Everything.exe 缺失崩 dsh 进程、气泡复制/就地编辑增强、alpha.1/alpha.3 两代 composer 适配）与 patch 分发文件全部摘除，现场补丁文件与声明由自愈链回收。退役后图片收发完全走上游原生链路
- **自研文件附件插件 dsh-file-attach 1.0.1（内置）**：文件/文件夹附件能力以与图片链路完全隔离的方式回归。输入栏新增 📎 按钮（对齐上游 + 按钮规格，Alt+点击选文件夹），拖入非图片文件/文件夹自动入队；文件经服务端定位链还原真实路径（浏览器文件选择只提供文件名，服务端在当前会话工作区内按名定位，多候选时 chip 点选、未命中标红）；发送时以 `[附件]名称|路径` 行注入 prompt，agent 按路径直接读取；气泡内附件行渲染为胶囊卡片（文件图标方块 + 文件名，悬停显示完整路径，目录带「目录」标记）。粘贴/拖拽图片不经过此插件（零参与、零监听），原生多模态链路不受影响。真源独立仓 kkutysllb/dsh-file-attach（MIT），经 dsh-plugins 镜像 → bundle/ 随包分发，BUNDLES 物化通道直写、不经 pnpm 安装

## 内部维护

- 附件能力宿主解耦：attach-picker.ts（152 行）删除，windows.ts 注入点与权限放行说明、相关注入器注释随动；update-profile-plugins 生效校验（PATCHES/PATCH_MARKS）与 profile-patches（PATCH_MARKS/PATCH_FALLBACKS/锄点）同步摘除 dta 条目并压缩为历史注释；electron-builder extraResources 补丁清单说明更新
- dsh-file-attach 分发链接线：sync-bundles 新增映射（产物直提包全镜像），kcoder-skills-bundle BUNDLES 表登记（entry.js + client.js 完整性校验）。不进 PRESET_PLUGINS——BUNDLES 物化通道与 pnpm 安装通道互斥（materialize 会将 BUNDLES 表包从 profile dependencies 拔除），零依赖插件直写物化即完整加载面（git-panel 同款先例）

## 升级注意

- 无需手动操作：drag-to-attachment 退役三清与 dsh-file-attach 内置物化均在重启后自动完成，已装用户启动即迁移
- 行为变化：粘贴/拖拽图片回归上游原生（图片数据随消息发送，多模态模型可直接读图）；文件/文件夹附件改经 📎 按钮或拖拽入队，气泡内呈现为附件胶囊卡片
