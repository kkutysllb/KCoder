# KCoder v0.6.27

> 发布日期：2026-10-09 · 上游基线：deepseek-harness **0.2.1-alpha.1**（`5badb15009`）+ fork 集成分支 kcoder/0.2.1-alpha.1（`161c7122f6`）——引擎基线**不变**，本版是 **v0.6.26 现场回归的修复版** + 一项桌面能力补全

## 修复

- **修掉 v0.6.26 的「加载提供商目录失败： settings are unavailable in this browser」（用户现场回报）。** 协议化加载后页面 origin 不再是回环地址（`kcoder-app://app` ≠ `127.0.0.1`），而上游客户端按「页面 origin 是否回环」判定本机特权面：设置镜像被判定为「非本机页面」后进入纯内存模式——不读引擎、无视图、也无错误，提供商目录两路列表都成功、唯独镜像两头空，正好兜底成这句报错。设置文档、聊天设置作用域也在同族静默降级。

  修复：上游在传输契约全局 `__DSH_TRANSPORT__` 里留了显式声明位 `ownsHost`——「只有自己组装传输层的壳才能设置」，上游自家的 worker 组合注入的就是同款双成员。我们此前只注入了 `streamBaseUrl` 一半，现补齐 `ownsHost: true`：客户端的本机特权判定恒为真（本产品页面只能经协议层触达本地引擎，声明属实），一处修复覆盖设置镜像、设置文档控制器、聊天设置作用域全部消费方。

  **防复发**：注入契约由逻辑门（62 断言，含 v0.6.26 旧注入形态必红的负对照）与真渲染进程冒烟（21 断言）双重钉死；协议层的「上游按环境分叉」代码面做了全类扫描（回环判定 / location / baseURI / Service Worker / SSE / 契约全局），确认无第二个同族回归。同轮把扫描结论补进了协议设计文档（`plans/kcoder-app-protocol.md` F6b）。

- **诊断与门禁补强（随修复入库）**：MCP 设置冒烟跟进 v0.6.26 的 DOM 契约变更、两处死导入清理——这些在 v0.6.26 发版审计中当场拦下并已随该版入库，此处一并说明。

## 新特性

- **从访达拖文件进输入框，直接成为 `@路径` 引用（不再字节上传）。** 上游 composer 本就支持把有真实路径的本机文件转为 `@绝对路径` 引用——agent 按路径直读文件，不经上传——但该能力依赖桌面壳提供一个取文件真实路径的单方法桥。本版以**最小单桥**补上（与上游官方桌面同款做法）：只在引擎页暴露 `pathFor` 一个方法，不携带宿主通道，`data-platform`、上游桌面分支全局一概不进页面（壳保持无 preload 的既有铁律，例外边界与守卫门见设计文档 D3）。粘贴截图、无路径文件照旧走字节上传，与 web 端一致。

  注：从**侧边栏文件树**拖文件进输入框这个手势在官方桌面同样不存在（原生树的拖拽只用于树内重排，输入框只认系统文件拖入）——引用工作区文件请用 `@` 补全或访达拖入，与上游一致。
