# KCoder v0.6.18

> 发布日期：2026-09-26 · 上游基线：deepseek-harness **0.1.7-rc.2** (477b4f4205) + fork 集成分支 3376ee9896

## 新特性：远程工作区（把 KCoder 跑在远端主机上）

- **连上一台 Linux 主机，拿到的是「跑在那台机器上的完整 KCoder」**：窗口里的终端、文件面板、Git 都在远端执行。不是「本地壳去访问远端目录」，而是把服务本身装到远端、本地只保留一条端口转发。
- **为什么是这个形状**：宿主侧客户端插件（文件树、Git、终端、媒体）都假设「本机就是那台机器」。让进程落在远端，这些假设全部成立，**一个插件都不用改**；反过来「本地进程 + 远端执行世界」要求每个插件都改成世界感知——`dsh-coding-sidebar` 一个插件就有 8 个文件直接使用宿主文件系统。
- **首次连接自动装配，之后秒连**：随包的运行时与内置插件按**远端平台**补齐后装过去（引擎的纯 JS 部分与本地同版本，原生包按平台从 npm 取，**版本因此与本地 bundles 天然对齐**）；此后按内容指纹跳过未变动部分。
- **配置随行**：模型供应商与密钥、MCP 服务器、界面偏好随连接同步到远端，不必在每台机器上重配一遍；密钥文件以 600 权限落盘。
- **过程可见、失败可读**：窗口立即打开并逐条显示阶段（装配 / 同步 / 启动 / 联通）；失败时把完整原文摊在窗口里，可选中复制，而不是一次性弹窗。
- **失败不阻塞**：引擎装载有界等待，超时后在远端已有可用引擎时先启动，装配留在后台继续。

接入路径：设置页「SSH 远程主机」添加主机 → 引导（首次装用户态 Node 与密钥别名）→「添加工作区」→「远程主机」→ 连接。

## 缺陷修复

- **工作区路径改为在挂载的执行世界里解析**：此前一律按宿主机文件系统处理，远程工作区下会出现 `cannot resolve target … realpath`，会话也建不起来（`failed to ensure project directory`）。
- **远端默认工作区按世界解析**：此前会把宿主的 `~/Documents/…` 形状路径**建到远端**，留下一个属于另一台机器的路径。
- **远端窗口与主窗口共用同一套外壳**：此前只挂了品牌注入，侧边栏、状态栏按钮、设置页、主题跟随全部缺失（观感是「裸的上游界面」）。
- **目录来源切换**：目录对话框新增「本机 / 远程主机」两个来源——本机仍走系统对话框，远程主机在**那台机器的窗口**里逐层点选（远程工作区只能建在它所属的世界里）；远程世界内直接给应用内浏览。
- **启动不再自动弹出远程窗口**：请求文件的起始序号此前被当作待处理请求处理。
- **`dsh-ssh-remote` 插件**：新增引导端点（公钥/别名 → 用户态 Node → helper → 登记世界）与远程连接入口，引导幂等；修复目录来源切换的状态更新（`useState` 被拆成两次调用，导致切换只重渲染、状态不变）。

## 引擎升级：多供应商模型目录全面刷新（pi-ai 0.85.1 → 0.87.1）

- 内置多供应商路由引擎（pi-ai）从 0.85.1 升级到 **0.87.1**，模型目录随上游完成一轮大刷新。本项先于上游官方（官方同版仍钉 0.85.1），由 fork 修复分支供给。
- **目录时效**：旧目录里积压了大量已下线型号（升级后这些路由会明确退出模型选择器，而不是在请求时报「模型不存在」）。
- **在位刷新**：几乎所有供应商的定价、上下文窗口与思考能力标志都有更新——用量估算与能力门控据此更准。

### 供应商目录变化（要点）

- **DeepSeek**：新增 `deepseek-flash`；`deepseek-v4-flash` 族移除（配置里还钉着旧型号的会收到明确提示，改用 `deepseek-flash` 即可，两者上下文/输出上限/思考档位一致）。
- **Moonshot**：清理 6 个 kimi-k2 预览/思考型号，仅保留现役 4 个。
- **智谱（zai-coding-cn）**：移除 glm-4.7 / 5.1 / 5.2 等旧代次。
- **OpenAI / Codex / Azure**：新增 gpt-6-luna、gpt-6-sol（Codex 通道同时移除 gpt-5.4 / 5.4-mini）。
- **Anthropic**：新增 claude-opus-5-5；**xAI**：新增 grok-4.7；**小米**：新增 mimo-v2.6 全系。
- **新增供应商**：meta、radius。
- **OpenRouter**：新增约 38 个型号（gpt-6 全家、grok-4.7、glm-5.3-flashx、deepseek-v4.1-flash 等），约 343 个型号的定价/能力在位更新。

### 引擎行为适配

- 0.87 的会话转写协议收紧（TranscriptContext 品牌类型、工具调用参数 JsonObject 化）已全部适配；回归面 `packages/llm + bundle/base` **1400/1400** 全绿。
- 随包运行时补丁（中转/网关兼容：codex accountId 兜底、中转流提前收尾容错、流式工具参数一次性解析）对 0.87.1 重打，内容零漂移。
- **工具缺陷修复**：本地物化脚本的依赖溯源此前按目录名「先到先得」，在同名多版本并存时会搬错实体（本次升级现场实测把旧 0.85.1 盖进产物）；已改为 semver 校验 + 同版本优先补丁体，并在发版链新增「版本 + 补丁标记 + 目录」三查断言。

## 升级注意

- 配置里若钉着被移除的型号 id（如 `deepseek-v4-flash`、`kimi-k2-thinking` 等），升级后对应路由会在选择器中消失并在设置页给出原因；改用各供应商的现役型号即可。
- OpenRouter 路由的会话亲和头（`x-session-affinity`）默认开启（上游行为），对多上级网关的用户属正向变化（提升缓存命中）。
