# KCoder v0.6.1

> 发布日期：2026-09-12 · 上游基线：deepseek-harness 0.1.5-rc.2 (fb2c4b9e)，集成分支 kcoder/0.1.5-rc.2（尖端 1fc823f08d）

## 修复

- **Windows 任务执行弹 cmd 黑窗（v0.6.0 修复打错层的真正根因）**：打包版引擎以 `Electron.exe + ELECTRON_RUN_AS_NODE` 运行（内置 runtime 原生模块按桌面 ABI 锁定，解释器不可换）——GUI 子系统进程**没有控制台**，v0.6.0 在桌面侧加的 `windowsHide` 对引擎链路完全无效。真正的弹窗链在引擎侧沙箱体系：
  1. Windows 沙箱 ACL runner 的解释器取 `process.execPath`（打包态同为 Electron.exe，无控制台）；
  2. runner 经 `CreateProcessAsUserW` 启动沙箱化的 pwsh / rg 时创建标志未带 `CREATE_NO_WINDOW`——父进程无控制台可继承，每条命令**新建一个可见控制台**，即「Pwsh 命令、Grep 命令逐条弹黑窗」。

  修复（fork 集成分支 fix/win32-console-window-hide）：`win32-process` 三处受限进程创建统一补 `CREATE_NO_WINDOW`（piped 由 0 改为该标志、inherited/current-token 载体叠加；abi 表新增常量，测试断言同步）；另有 7 处引擎内 `child_process` 调用补 `windowsHide`（sdk client 启动 runtime、`dsh plugin` 的 pnpm 调用、python code-runtime 探测与运行、web-app 开浏览器 launcher、进程快照 ps 调用、沙箱三处功能性探测）。上游 CLI（控制台子系统 node）的 IO 全走句柄管道，行为不变。
- **Windows 深→浅→深标题栏卡浅色（自绘条 + 原生按钮区双层治理）**：标题栏底色条为 KCoder 自绘 div——主题落点突变后上游 CSS 变量可能异步落定（@property 过渡不产生后续 DOM 变化），自绘条在突变瞬间读到旧值后不再有重画时机；现在页面脚本每次主题变化后 120/400ms 各重读重画兜底，并直听 `prefers-color-scheme` 媒体查询、观察 html/body 的 class 变化，暴露 `__dshTitlebarApply` 供主进程在主题事件时 poke。右上角最小化/最大化/关闭按钮为 Windows 原生 WCO 叠画（底色走 `setTitleBarOverlay`）：切主题时窗口在后台，DWM 会丢弃调用且定时重放一并丢弃——重放间隔放宽为 0/250/800ms，并新增窗口 `focus` / `restore` / `show` 时按最近参数整体重放，覆盖后台丢弃的所有时序。
