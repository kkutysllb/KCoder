# KCoder v0.6.20

> 发布日期：2026-10-01 · 上游基线：deepseek-harness **0.2.0-rc.2**（639ed01539）+ fork 集成分支 b428f93a79（与 v0.6.19 同基线，本版为缺陷修复）

> 发布结果：CI 三平台全绿（[run #76](https://github.com/kkutysllb/KCoder/actions/runs/36792501642)，2026-10-01），产物已上线——macOS `KCoder-0.6.20-arm64.dmg` / `.zip`、Windows `KCoder-Setup-0.6.20.exe`、Linux `KCoder-0.6.20.AppImage` / `.deb`。CI 侧新增的「内置 provider 随包断言」在 ubuntu / macos / windows 三个 runner 上均通过，这是本次修复的跨平台终局验证。

## 修复

- **Windows 上使用 npm 镜像源的用户：插件管理页出现 4 条「异常」，且任何插件的安装/更新都会失败。**

  v0.6.19 把 4 个 SSH 运行时包（`@deepseek-ai/dsh-ssh`、`dsh-fs-ssh`、`dsh-subprocess-ssh`、`dsh-sandbox-ssh`，钉 0.2.0-rc.2）登记进用户 profile 的依赖，由用户侧 `pnpm install` 安装。当镜像源尚未同步该版本时（npmmirror 对 0.2.0-rc.2 滞后一天以上，实测仍 404），声明悬空，产生三类后果：

  1. dsh 插件管理页把这 4 个包列为「已安装」并打「异常」红标（它们是内置 bundle `dsh-ssh-remote` 的运行前提，不是插件）；
  2. 整棵 pnpm 依赖图解析失败——**任何**插件的安装/更新都报错（点「更新 dsh-context」即被拖垮，退出码 1）；
  3. 每次启动空转一次注定失败的安装（约 22 秒）。

  本版把这 4 个包改为**随引擎分发**：由构建链在物化运行时的时候一并供给并登记进引擎清单，运行时从安装锚点解析。因此：

  - 不再依赖用户 registry 是否已同步该版本；
  - 它们不再出现在「设置 → 插件」的「已安装」列表里（provider 不是插件）；
  - 升级后首次启动会幂等清理旧 profile 里的残留声明与副本，不需要用户手动操作。

- **防止复发**：新增「内置 provider 随包」断言，本地发版链（`release.sh build` / `verify`）与 CI 三平台构建各断一次——产物里缺这 4 个包直接红，而不是留到用户侧表现。

## 升级注意

- **受影响的 0.6.19 用户升级即恢复**，无需手动改 registry、也无需手动安装任何东西。
- 若你此前为绕过该问题手动改过 pnpm registry、或在 profile 里装过这几个包：升级后**不需要回退**——自愈逻辑会清掉 profile 侧的声明与副本，改过的 registry 配置保持你自己的设置不动。
- 远程工作区（SSH 执行世界）能力不受影响，运行前提已随引擎分发。

## 已知问题（与本版修复无关的既有项，沿用登记）

- `smoke-panel-buttons` 冒烟失败：标题栏第四枚按钮的平移规则从未写入 `SHIFT_JS`（v0.4.6 起如此）。
- `smoke-skills-dom` / `smoke-skills-page` 冒烟挂起：构建期插值常量与冒烟提取方式不匹配（v0.5.9 起如此）。
- `dsh-context` 预置声明版本漂移（声明 `^0.55.0` vs 实装 0.56.2+）：补丁链已随 0.6.19 重出到 0.60.0，声明线平移待下一轮。
