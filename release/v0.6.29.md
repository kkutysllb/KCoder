# KCoder v0.6.29

> 发布日期：2026-10-10 · 上游基线：deepseek-harness **0.2.1-alpha.2**（`d7432673`）+ fork 集成分支 kcoder/0.2.1-alpha.2（`41f151ab20`）——**引擎基线不变**，本版是 v0.6.28 现场回归的修复版（五处**打包态专属**缺陷）

## 修复

- **右栏终端报「终端错误：posix_spawn failed: Permission denied」（macOS / Linux 打包版）**：随包运行时的 tar 归档把头里的文件权限写死成 `0644`，`node-pty` 的 `spawn-helper`（必须 0755）因此丢掉执行位——第一次开 PTY 就被系统拒绝。修复：权限取自源文件，并新增**归档回读自检**（写完后复读 tar 头，逐条核对「源文件可执行 ⇒ 归档项必须带执行位」，不符即拒绝出包）。dev 态走 node_modules（755），所以此前只在打包版复现。

- **实验性插件页「持久终端」组件显示异常：`a PTY backend named "shell" is already registered`**：上游 terminal-bundle 把 `optional-terminal-bash` 与 `optional-terminal-pwsh` 定义为**同一个包的两个 entry**（按平台互斥），但插件页可以打开「对手平台」那一个，引擎会把显式 `disabled: false` 写进 profile，压过平台条件 ⇒ 两个 entry 同时注册名为 `shell` 的 PTY 后端。修复：宿主启动期按平台**归一**对手 entry 为 `disabled: true`（幂等、只改该键的值；entry 不存在则不新增）。

- **实验性插件页 Codex / Claude Code 子智能体报「requires its complete workspace checkout」**：这两个是上游的**按需安装**官方 bundle（npm 上有 0.2.1-alpha.2），而上游安装器只看运行安装锚点的清单——我们随包 runtime 的锚点清单是**工作树形态**（89 个依赖里 71 个 `workspace:`），于是被判成「源码检出」而拒绝安装。修复：归档前把锚点清单归一为**已发布安装形态**（`workspace:` 规格写回具体版本），引擎随即走 `name@version` 的 registry 路径。

- **用户自装的 `@kkutysllb/dsh-git-panel` 每次重启后消失、需重装**：我方退役名单里留着它的**旧名**（`dsh-git-panel` / `@dsh-external/dsh-git-panel` / `@kcoder/git-panel`），而该名单是「每次启动三清」（依赖声明 + 层叠 + 实体）——与现行插件同处一个 profile 时来回打架，装好即被下次启动洗掉。修复：**移除冲突旧名**，并加静态防线（退役名单不得包含 git-panel 系）；同时把孤儿判据改保守——**实体在位绝不判孤儿**，用户插件即便声明丢失也不会被删实体。

- **工具链**：`smoke-bundle-profile` 的 esbuild 补 `@shared` 别名（与 tsconfig / electron-vite 同源）——该冒烟现编主进程模块，缺别名会导致门红而 tsc 与运行时都正常。

## 再补一处：自装插件每次重启被清掉（本版收口）

- **`@kkutysllb/dsh-git-panel` 装好后每次重启消失、需重装** —— 根因是内置插件退役名单 `RETIRED_PLUGINS` 里持有该插件的**现行全名**：它 2026-09-14 因「右侧栏 Git 面板已覆盖其能力」退役，而**右侧栏插件已于 2026-10-09 整线退役**，理由不复存在；名单却是每次启动三清（依赖声明 + 层叠 + 实体）。已从名单移除（un-retire）并加静态断言「名单不得含 git-panel 系」。

  定位方式：安装日志里对它的操作**全是安装、没有卸载** → 排除 pnpm 卸载；把**真实启动函数**放进隔离 `DSH_HOME`（拷真 profile + 装回插件）复现出 `[kcoder-bundle] 清除 profile 退役/孤儿插件残留: deps=[@kkutysllb/dsh-git-panel]`；移除名单项后同一复现中 deps/bundles/实体**全部存活**。

## 验证

- 仓库聚合门 `pnpm check` **39/39**；新增三处断言并有**负对照**实证：归档执行位自检（模拟写死 0644 ⇒ 红）、平台互斥归一（两处 `true` 改 `false` ⇒ 6 项红）、孤儿判据（去掉「实体在位」⇒ 2 项红）。
- 修复面实证：tar 头 mode 往返（源 0755 → 归档 `0000755`，系统 tar 读回 `-rwxr-xr-x`）；已装 runtime 现场应用锚点归一（108 个 `workspace:` 依赖 → 具体版本，复算上游判据 `source = false`）。

## 升级注意

- **v0.6.28 用户建议尽快升级**：本版修的四项都在打包版才会显形（终端、持久终端组件、两个子智能体、自装插件被洗）。
- 随包 vendor 的 pnpm 由 `11.7.0` 提升到上游声明的 `11.28.5`（同主版本 11.x，profile store 大版本不变，**无需手动迁移**）。
- 若你在 0.6.28 上手改过 `~/.kcoder/profiles/web/package.json`，升级后一切照旧；无需其它动作，重启应用即生效。
