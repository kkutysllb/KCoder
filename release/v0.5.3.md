# KCoder v0.5.3

> 发布日期：2026-09-02 · 上游基线：deepseek-harness 0.1.2-alpha.4 (4e84901e)

## 修复

- **历史任务列表初载标题缺失，根因修复（本版主题）**：升级 alpha.4 后，历史任务（会话列表）初次打开显示的是工作区目录名而非标题，需逐个点开会话才能恢复；未点开的任务每次启动继续缺失。根因：alpha.4 上游给会话投影缓存（session_projcache，域版本 4 → 5）的条目身份新增 `isSeeded` / `inheritedEventCount` 两个必填字段——缓存条目自此绑定到具体会话生命周期，防止同 id 换日志后旧缓存误发；旧引擎写入的缓存因身份失配被整体判废。缓存值（标题、统计、用量等投影）完好无损，但读取层全部按缺失处理；列表读取对大日志不做冷读（防启动性能塌方），标题投影缺席时界面回退显示目录名。本版在引擎读缓存前的启动窗口做一次性就地迁移：版本号对齐 + 身份补 `isSeeded: false` / `inheritedEventCount: 0`，缓存值零重算——升级后首次启动即恢复全部历史任务标题，无需逐个点开。
- 迁移安全性：幂等（已迁移即跳过，unit 文档为提交点）、原子写（tmp + rename）、迁移前自动备份（`storages/session_projcache.json.bak-projcache-v3`）；补默认 `isSeeded: false` 不会误发旧值——真 fork 会话的身份与补出值不匹配，继续按缓存缺失处理，与迁移前行为一致；迁移失败不阻断启动，仅退回升级前的回退显示状态，由引擎按缓存缺失自愈。

## 内部维护

- 新增 projcache-migrate 启动序模块（`dshManager.start()` 之前执行，引擎读缓存前的串行窗口无并发写）；分片文档（per-record 布局）与 unit 索引双层版本同步对齐，单份分片坏档跳过不拖垮整体。

## 升级注意

- 无需手动操作：升级后首次启动自动完成缓存迁移（日志 `[projcache-migrate] 域 v3 → v5`），历史任务标题即恢复。
- 如需回滚迁移：退出应用后删除 `~/.dsh/storages/session_projcache.json` 与 `~/.dsh/storages/session_projcache/`，再将 `.bak-projcache-v3` 复原为 `session_projcache.json`（回滚后列表标题回退现象会重现，属预期）。
