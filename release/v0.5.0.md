# KCoder v0.5.0

> 发布日期：待定 · 上游基线：deepseek-harness 0.1.2-alpha.3 (dd6322d6)

## 变更

- **上游基线升级 0.1.2-alpha.2 → alpha.3**：引擎全面升级，以下新能力随基线带入
- **长会话轮次导航与跳转**：对话视图新增右侧轮次导航条，可预览各轮次摘要并点击跳转；跳转目标轮次尚未载入本地窗口时自动向后翻页加载到位，长会话翻阅历史不再需要手动一页页「加载更多」
- **长会话渲染性能优化**：会话渲染内存占用下降，代码块语法高亮改为视口外延迟执行，长对话滚动更流畅
- **运行中排队图片可靠回显**：会话运行期间提交的排队/插队消息附带图片时可靠投递与回显，含持续子代理的后续消息场景；排队消息新增「插队（steering）」呈现标记
- **命令菜单 Tab 补全**：输入 `/` 唤出的命令菜单支持 Tab 键补全
- **read_image 按内容识别无扩展名图片**：附件读取对无扩展名图片按文件内容识别格式，不再误判为文本
- **权限标签多语言**：权限预设标签随界面语言本地化
- **模型目录更新（pi-ai 0.84.4）**：新增 glm-5.3-flash / glm-5.3-highspeed 等模型目录
- **连接稳定性修正**：后端短暂卡顿不再被误判为断连而终止会话（WebSocket 心跳改为连续漏跳计数制）
- **定时计划列表窄视口修复**：窄窗口下计划目录列表对齐异常修正
- **Windows 升级启动崩溃修复**（0.4.9 测试包期发现）：上游基线 alpha.2 起引擎设置模块移除了 settingsNamespace 导出，升级用户 profile 里残留的旧版插件（dsh-context 0.37.x / dsh-better-sidebar 0.17.1）加载即语法错误，导致整个应用拒绝启动。现 dsh-context 预置版本升至 0.38.5（适配新契约），旧版实体由版本对账自动摘除重装；dsh-better-sidebar 改为收编产物随包分发，启动时自动覆盖 npm 残留实体为收编 0.17.2——升级后首次启动全链自动修复，无需手动处理
- **拖拽/粘贴附件卡片渲染修复（alpha.3 槽位适配）**：引擎槽位守卫会丢弃预置插件的显式优先级（按注册顺序重新排名次），dsh-drag-to-attachment 的用户气泡影子渲染由此退化为先到先得——任何更晚懒注册同一格位者无声胜出，拖入图片的 `[附件]名称|路径` 行以裸文本暴露。现重写其影子注册：同时占住 user 与新增 steering 两个格位、注册后自查格位归属、被抢即弃注重注（新名次必更低必胜）并持续盯防；修复经补丁分发链随包发布，已装用户启动自动自愈，无需手动处理
- **侧边栏切换自立插件 dsh-coding-sidebar 1.0.1（内置）**：侧边栏工作台（文件树/编辑器/终端/Git/预览）从收编线正式切换到自立发布线——fork 自 DSH-better-sidebar 0.17.2、与上游版本号空间完全切割、底面板产品裁剪（源码级移除，界面无底面板，旧底面板持久化数据自动迁移不丢 tab）、产物版本常量改为构建期从 package.json 注入（单一事实源）。服务点名 betterSidebar、DOM 锚点 data-dsh-better-sidebar、路由前缀 /sidebar/api 全部保留，衍生插件（office/视频预览/docs 面板/流镜/ssh 隧道等）零改动兼容；旧插件 dsh-better-sidebar 从 profile 三清退役，此后重装衍生插件时其 peer 依赖会从 npm 拉上游真包实体——该实体不进加载层叠不会被加载（无双跑），仅作 peer 满足与类型来源

## 内部维护

- 上游基线升级以集成分支重建：fork 五修复分支（pi-ai 升级 ×2、codex 协议回退、markdown 跨行合并、projection 缓存隔离）与品牌化、imageRequestPricing 两笔 cherry-pick 全部在 alpha.3 上重新合入，与上游的 2 处集成冲突已双侧合并，差异文件列表与上游完全一致（完整性断言通过）；全部注入锚点逐项核对存活
- upstream/0002 归档改名对齐 pi-ai 终态 0.84.4（维护记录，不影响构建）
- 预置插件新增 spec 漂移对账（只升不降）：实体版本低于预置下界时自动改写依赖声明并重装，此后预置 spec 升级可推送到已装用户；github tag 形态 spec 的 tag 版本同样参与对账，link: 等无版本形态不参与
- dsh-better-sidebar 分发路径重构：profile 依赖声明的 ^0.17.0 仅作依赖树牵引（pnpm install 把 codemirror/ws/node-pty 等装到 profile 顶层），实体终态由随包 bundle 物化覆盖；主进程在预置安装后二调 bundle 物化兑现纠偏；发版对账链同步拦截包内 bundle 目录缺失（extraResources 映射漂移）
- 发版链新增上游 vendor/ 纯净 preflight（verify-vendor-purity.sh）：物化/手工 deploy 的残留目录会被上游 tsdown workspace glob 当成假成员、以根包名义报 Cannot find entry 炸掉上游构建（rc.5/alpha.2/alpha.3 三次复发），构建前无条件过闸
- drag-to-attachment 补丁链扩展：宿主 patch 追加影子注册重写 hunk；生效校验 marks 双处同步（profile-patches / update-profile-plugins）；锄点兑底新增 CRLF+LF 双锚整块替换规则，分别对准全新解包 tarball 与 patch 残留产物两种行尾现场
- 侧边栏分发链重构为两级镜像：独立仓 kkutysllb/dsh-coding-sidebar（真源，自带 dsh-plugins 镜像同步/prepack 冒烟/GitHub Release 脚本）→ dsh-plugins/dsh-coding-sidebar → KCoder bundle/kcoder-coding-sidebar（sync-bundles 映射切换，旧 kcoder-better-sidebar 物料退场）；bundle 物化、预置 spec（^1.0.0）、版本兜底对账（VERSION_ALIGNS）、extraResources、release.sh 对账全部随新包名接线
- dsh-better-sidebar 旧线三清退役（RETIRED_PRESETS 自愈）：bundles 层叠摘除 + profile deps 声明摘除（含历史 git+ssh 引用形态）+ node_modules 实体删除，pnpm install 重放按新依赖图收敛（不走纯 rm 路径，图与磁盘一致不漂移）；$DSH_HOME/settings.yaml 标题栏避让补写键随新包 settings namespace 改名（dsh-coding-sidebar.titleBarCompat/titleBarStripPx，旧键残留无害）
- @tt-a1i/archify-dsh 预置退役（同走 RETIRED_PRESETS 三清自愈）：架构图能力由自有插件 dsh-super-ppts 覆盖，后续 dsh-animation 插件亦将具备该能力，第三方重复能力不再预置；纯技能包装零依赖零迁移，声明/层叠/实体三处自动清理，按需可经插件管理页自装；退役实体清理顺带增强：@scope/name 形态包删除后空 scope 壳目录一并清（pnpm 图收敛不管空壳）
- **内置插件全系改名自立（@kcoder/* → dsh-*，六包独立发布）**：dsh-git-panel / dsh-stats-panel / dsh-terminal / dsh-language-bundle / dsh-skills-bundle / dsh-file-review-kcoder 六包从内置 @kcoder/* 命名全部迁出为 kkutysllb 下同名独立仓（1.0.0 起步，开发真源迁址；file-review 同步脱离 fork 形态完全自立，血缘 left0ver/dsh-file-review MIT 署名保留），三级分发链为独立仓 → dsh-plugins 镜像 → bundle/（sync-bundles 映射与 extraResources 全部随新目录名重接线）；bundle 物化常量/BUNDLES 表、技能目录扫描（skills-catalog）、设置页文案随新包名接线；旧名六包列入 RETIRED_PLUGINS 自愈三清（旧 bundles 层叠项/物化目录/历史 deps 残留声明，@kcoder 空 scope 壳一并清）；跨层持久化协议锚点保留不动（language 的 patch 行 id kcoder-language 与 section 名 kcoder:language、宿主↔插件 DOM 锚点 __dsh_kc_term_btn/__dsh_kc_git_btn），老用户重启即自动迁移到新名实体，声明与层叠零残留

## 升级注意

- 无需手动操作：基线升级为全新引擎产物，重启 KCoder 即生效
- 上游移除了可选的 SQLite 会话持久化后端；KCoder 默认使用 JSONL 持久化（从未启用该可选后端），存量会话数据不受影响
