# KCoder v0.6.28

> 发布日期：2026-10-10 · 上游基线：deepseek-harness **0.2.1-alpha.2**（`d7432673`）+ fork 集成分支 kcoder/0.2.1-alpha.2（`41f151ab20`）——**引擎基线升级版**：alpha.2 的完整落地 + 两项内置插件退役 + 工作台加载形态收口

## 引擎基线升级（0.2.1-alpha.1 → 0.2.1-alpha.2）

- 上游 512 个提交 / 3226 个文件（+114987 / −28177）。发布说明**逐条**落地核对见 `docs/upstream-0.2.1-alpha.2-analysis.md`（47 条 + 官方升级指南 20 主题 + 13 项**官方未提及**的结构性变更），实施与判据见 `…-upgrade-plan.md`，机械核对与 34 条判定见 `…-verification.md`。
- **上游 11 个实验性组合包随版打包并默认选中**（含智能体团队、语音输入等；此前为 4 个）——装好即用，无需手动装插件。

## 内置插件退役（两项）

- **右侧边栏插件退役**：右侧工作台交回上游原生右栏（铁律 1 翻转，2026-10-09 拍板）。
- **内置终端插件退役**：终端交回上游原生能力。

两个退役包在升级后会被宿主**三清自愈**（声明/物化/入口），已装用户不会残留半截插件。

## 桌面与产品面

- **工作台协议化加载成为唯一形态**：`kcoder-app://` 由主进程转发引擎请求，页面全程不暴露 `127.0.0.1`；legacy 直连路径与其偏好开关**退役**（不再有回退档）。
- **与上游桌面壳 `dsh-app://` 对齐**：WebSocket 支持 TLS 侧车（`wss://` + 协议匹配），就绪行接受 `https`（配合上游新增的 `--tls-cert/--tls-key` 原生 HTTPS 监听）。
- **注入面字体跟随上游设置**：39 处写死字号改为继承（跟随「界面正文 / 代码与工具输出 / 侧栏终端」字号设置），并加不变量闸（新增即失败）。
- **landing 右侧滚动条改为无痕**（可滚动、不显示、不占宽）。
- **工作区名显示退役**：标题栏的「工作区 / 标题」前缀与那枚工作区按钮按产品判断删除（含一度试做的官方槽版本）。

## 修复

- **`dsh-shell-prefs` 插件激活失败**（`import failed: require is not defined`）：client 半工厂漏声明 `require` 形参（上游契约是 `factory(require)`）。已修复，并把「加载器契约仿真」做成常备闸（工厂必须收形参 + 桩模块调用不得抛错，负对照实证）。
- **远端主机平台探测失败不再只报「(空)」**：连接未返回结果时如实回报原因；中转拒连文案纳入传输层重试判据。
- **内置插件 `dsh-ssh-remote` 0.1.5**：`ssh_edit` 支持期望哈希 token（并发冲突在**写前**拒绝，不再覆盖他人改动）；建连遇瞬时拒绝自动重试（3 次、2s→8s 退避）。
- **审计脚本修正**：`UNUSED DEPS` 读错 depcheck 键位（`using` 是「已使用」映射），此前把 10 个在用依赖误报为未使用；两项真死导出（`openRemoteHostIds` / `remoteInstallReady`）按「修复」删除。
- **工具链单源收口 + Windows 可移植性**：上游克隆落点、构建用 pnpm、集成分支名各收敛为一份唯一实现；冒烟统一跨平台入口（Windows 下 `pnpm run smoke:*` 不再报 `'env' is not recognized`）。

## 升级注意

- **协议加载为唯一形态**：偏好设置里的「工作台协议加载」开关已移除；如遇协议层问题，诊断页会显示「加载：kcoder-app 协议转发」+「引擎状态」，请把这两行一并反馈。
- **随包 vendor 的 pnpm 由 `11.7.0` 升到上游声明的 `11.28.5`**（同主版本 11.x，profile store 大版本不变）——对既有用户**无需手动迁移**。
- 两项退役插件若你此前在用：右侧工作台与终端请改用上游原生入口（数据与工作区不受影响）。
- 无需其它手动迁移；重启应用（或托盘「重启引擎」）即生效。
