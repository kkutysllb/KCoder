# KCoder v0.6.24

> 发布日期：2026-10-04 · 上游基线：deepseek-harness **0.2.1-alpha.1**（`5badb15009`）+ fork 集成分支 kcoder/0.2.1-alpha.1（`161c7122f6`）——**本版是一次引擎基线升级**（0.2.0-rc.2 → 0.2.1-alpha.1）

## 升级

- **引擎基线升级到 deepseek-harness 0.2.1-alpha.1。** fork 集成分支从新基线重建并已并入我方全部偏离面（61 文件，集合断言 `comm -3` 为空），上游 266 个提交 / 4190 个文件的变更全部进入本版。集成后的自测：上游 vitest **12569 通过**，其中 2 项失败经**纯净上游工作树**复跑确认为上游既有问题（与本产品无关）。

- **修掉两个内置插件在升级后会被静默跳过的问题。** 它们的 peer 上界写的是 `<0.2.0`，而引擎版本变成 `0.2.1-alpha.1` 后该条件判定为假——引擎不会报错，只会打印一行 `skipping profile bundle` 然后**不加载**：内置终端与 SSH 远程会变成「界面在、功能没有」。已按新基线放宽 peer 口径（终端 `1.2.2`、SSH 远程 `0.1.4`），并同步 `engines.dsh`、各仓自测常量与 README。**这是本次升级里最危险的一类问题：不崩溃、不报错、只是能力缺失。**

## 变更

- **退役内置「改动审查」插件（`dsh-file-review-kcoder`）。** 它的能力（会话变更行 + 交付卡）有一半依赖它渲染，因此本版把内置的交付卡渲染器改为自行承担（`ui-deliverables.tailCard`），保证变更行与 `present` 交付卡仍然显示。侧栏的「审查」页签不再提供；**未提交改动的文件不会被自动丢弃**，只是不再有那个专属视图。已装老版本的用户 profile 里的残留声明与实体由启动自愈清理。

- **恢复上游的工作区侧栏「插件」入口。** 此前本产品把它挪到了「设置 → 内置插件 → 插件管理」并隐藏了侧栏入口；现在**两个入口并存**（同一页面，安装/启停/卸载/逐插件配置）。设置里的插件管理**保持不变**。

- **侧栏折叠栏改为无痕。** 折叠态的整列宽度归零、不再显示折叠把手与分区标签（与官方 macOS 折叠形态一致）；折叠时不再渲染「新建工作区」与搜索两枚图标按钮，相关操作改为「先展开侧栏、滑动结束后再打开」，避免锚点不存在时的定位错位。

## 修复

- **修掉三处会让插件「静默消失」的 profile 自愈缺陷**（都是不崩溃、只打一行日志的那一类）：
  1. **退役清理没有触发依赖收敛**：老 profile 里残留的旧版调度相关包会被新引擎的 peer 校验判为不兼容并**禁用整个任务计划功能**。现在清理命中后会真正执行一次依赖收敛。
  2. **侧边栏插件的依赖声明被误摘**：该声明是牵引依赖树用的（pnpm 需要它来提升 `node-pty`/`ws`/`codemirror`）。升级把版本对齐之后，判据翻转导致声明被摘掉——此后**任何一次插件操作**都会把插件实体当多余包删除（再靠启动自愈补回，反复抖动）。现在牵引声明无条件保留。
  3. **上游「可选组合包」被当孤儿删除**：协作团队 / 语音输入 / 自动评审 / 检查器属于引擎随附、默认关闭、由插件页开启的能力，实体来自引擎安装树而非 profile 依赖，于是每次启动都被清一遍——**用户开启过的能力静默消失**。现在这些包被正确识别为「引擎提供」，不再删除。

- **修掉三支坏掉的冒烟测试。** `smoke-panel-buttons` 的断言停留在 v0.4.6 的界面（第四枚按钮早已随插件退役移除），`smoke-skills-dom` / `smoke-skills-page` 自 v0.5.9 起一直**挂起**（构建期插值常量与提取方式不匹配）。三支现已全部修复并通过——**坏测试比没有测试更糟，它会把真回归淹在噪声里**。

- **开发环境：依赖陈旧哨兵 + 安装复用仓内 store。** 上游克隆的依赖装旧了会在启动时给出可照抄的修复命令（只告警不阻塞）；`setup.sh` 安装前按既有记录复用 store，避免把依赖装进另一份 store 造成体积与混乱。

## 升级注意

- 无需手动迁移；重启应用（或托盘「重启引擎」）即生效。首次启动时会自动收敛老 profile 的插件残留（一次性，日志会出现一条 `清除 profile 退役/孤儿插件残留`）。
- 侧栏「审查」页签随插件退役移除；未提交的改动不受影响。
- 本次升级涉及引擎基线，若你使用了自定义的 profile 补丁层，建议重启后确认相关注入页正常。
