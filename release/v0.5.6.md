# KCoder v0.5.6

> 发布日期：2026-09-05 · 上游基线：deepseek-harness 0.1.3-alpha.1 (d347e703)

## 退役

- **内置附件插件 dsh-file-attach 整线退役（上游原生能力到位）**：当前基线（0.1.3-alpha.1）的输入框已原生集成附件上传入口（引擎 web-app bundle 注册的 ui-attachment + file-upload 链路），内置的 @kkutysllb/dsh-file-attach 能力被原生覆盖，就此退役。该插件同时是 Windows 启动崩溃的根源——它自 0.5.1 起漏配安装包资源映射，安装包内从无实体，而部分用户的 profile 清单引用了它（经插件页安装过、或迁移自含它的旧数据），引擎启动解析失败即崩（cannot resolve profile bundle）。退役自愈三清：profile bundles 层叠残留摘除、deps 声明摘除、物化/安装实体删除——升级后首次启动自动完成，受影响 Windows 用户重启即恢复，无需手动处理。

## 修复

- **Windows 数据迁移报「没有权限 rename」**：Windows 与 POSIX 不同，旧目录树内任何句柄未释放（引擎子进程退场延迟、杀毒软件/索引器实时扫描）整库搬移即报无权限。现搬移带指数退避重试（约 4 秒窗口消化句柄释放延迟）；仍失败时错误提示给出 Windows 针对性指引，引擎在旧目录原地恢复、可重试。
- **CI 发布链补内置插件随包对账闸**：本地打包验证有「内置插件随包对账」，CI-only 发布链一直没有——这正是附件插件漏配五版未被发现的原因。新闸在打包后逐目录对账 bundle/ 清单与包内 resources，并核对插件热补丁，缺任一即拦截发布。

## 升级注意

- **Windows 受影响用户**：升级后首次启动自动清理退役插件残留，启动即恢复，无需手动操作；数据迁移此前报「没有权限」的，在设置页重新发起即可（已带重试；仍失败请先关闭占用旧数据目录的程序）。
- **附件功能**：输入框附件上传入口由引擎原生提供（拖入文件/粘贴与此前一致），退役插件不再参与，功能不受影响。
- **macOS / Linux 用户**：无行为变化，可正常自动更新。
