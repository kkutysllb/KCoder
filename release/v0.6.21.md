## 修复

- **arm64 远端主机连不上：永远「远端服务等待就绪超时」（日志字节 8226 / 入口存在 是 / 监听 0）。**

  远端连接需要按目标平台补几个原生包（`node-addon-require-builtin`、`@deepseek-ai/node-addon-system`、`sharp`、`koffi`、`ripgrep`、`sherpa-onnx`）。此前这份清单的命名族被**写死成 linux-x64**，于是 aarch64 目标机上 npm 以 `EBADPLATFORM` **整单拒绝**；而安装脚本既不检查退出码、末尾又无条件报成功，失败因此被吞掉、还照写了「引擎已就位」指纹——**坏状态永久粘滞**，之后每次重连都被判为「无需安装」。

  本版：

  - 连接时**探测目标平台**（系统 / CPU / C 库），据此从本地运行时派生规格清单；
  - 指纹**含目标平台**——已连过的机器首次连接即不匹配，自动重装一遍（这就是迁移，无需手动清理）；
  - 安装判据从「脚本打印了成功字样」改为**真的 `require` 一次原生绑定**，并加 `set -e`；
  - 平台不受支持或规格覆盖不足时**在安装之前**就明确报错，而不是装出一棵坏树再等 180 秒超时。

- **部分主机上每次连接都会重传整个运行时（约 485MB）。**

  引擎版本探测此前用裸 `node`，而由引导流程安装的 Node 不一定在非交互 SSH 的 PATH 里；探测因此恒为空，跳过条件永远不成立。改用引导流程记录的那个远端 Node 的**绝对路径**。

- **远端插件管理页对若干实验性插件报「包元信息错误」。**

  报错形如 `…/locale/._en.json must use a language id as its filename`。`._` 前缀是 macOS 的 AppleDouble 伴生文件（扩展属性/ACL 的旁挂表示），随传输落到远端；而插件管理页会把 `locale/` 目录下**每个 `*.json`** 的文件名当作语言 id 校验，一个 `._en.json` 就让整个包显示为「包元信息错误」。本版在传输链上双向设防（打包侧不产生、解包后就地清理），已在实机验证。

- **内置补丁链的「哑点」修掉（内部改动，但决定修复能否走标准路径）。**

  `dsh-context` 有两条常驻修复（RO 回路冷却、上下文跳转一律走会话内 tab）。面向它的补丁声明一直停在旧版本键，插件升版后 pnpm 把这处声明判为「未用」而不应用——修复实际上靠 App 启动时的兜底注入落位，能生效但依赖兜底。本版把补丁**重出到当前实装版本键**并同步声明，两条修复重新走标准路径。重出前做了逐字节取证：对未打补丁的当前版本应用本补丁，产物 md5 与线上实装产物 **完全一致**。

## 升级注意

- **已连过的远端主机：升级后首次连接会重装一次引擎**（重传约 485MB + 远端 npm 装包，几分钟），日志会依次出现「远端 linux-arm64/gnu」「原生包已补齐」「远端引擎就绪」。这是刻意的自愈，**不需要手动操作**；之后恢复秒连。
- **macOS 远端与 musl（Alpine）远端现在会被明确拒绝**并给出原因。此前这两种目标会装出一棵缺原生绑定的树，表现为等满 180 秒的就绪超时。
- 内置插件 `dsh-coding-sidebar` 升到 1.0.36：已装用户升级后由内置物化覆盖为终态，**无需手动更新**。
