# KCoder v0.6.30

> 发布日期：2026-10-10 · 上游基线：deepseek-harness **0.2.1-alpha.2**（`d7432673`）+ fork 集成分支 `kcoder/0.2.1-alpha.2`（`41f151ab20`）——引擎基线不变，本版是**一处静默数据损失**的修复

## 修复

- **你自行安装的 `@kkutysllb/dsh-git-panel` 每次重启后被静默清除、需要重装。**

  根因（**纯我方 bug，已在隔离 profile 上复现并验证修复**）：内置插件退役名单 `RETIRED_PLUGINS` 里持有该插件的**现行全名**。它 2026-09-14 因「右侧栏的 Git 面板已完整覆盖其能力」被退役——而**那个右侧栏插件已于 2026-10-09 整线退役**，退役理由不复存在；名单却是**每次启动三清**（依赖声明 + bundles 层叠 + node_modules 实体），于是用户装好的插件在下一次启动被静默删掉声明与实体。

  证据链：`.plugin-manager` 的安装日志里对它的操作**全是 `+`（安装），没有任何 `-`（卸载）**——说明不是卸载，而是启动期被删；把真实启动函数放到隔离 profile 上跑，复现出 `[kcoder-bundle] 清除 profile 退役/孤儿插件残留: deps=[@kkutysllb/dsh-git-panel] bundles=[@kkutysllb/dsh-git-panel]`，三个函数跑完后 deps/bundles/实体三者尽失。移除该名单项后同一复现中三者**全部存活**。

  修复：从退役名单移除该插件（un-retire，同 dsh-file-review-kcoder 的先例），并把「名单不得含 git-panel 系（含现行全名）」做成静态断言。**判据教训入档**：退役理由被后续退役动作推翻时，必须同步复查所有依赖该理由的名单。

## 验证

- 隔离复现（真启动函数 + 临时 DSH_HOME + 真 profile 拷贝）：修复前三者尽失 → 修复后 deps/bundles/实体**全部存活**。
- `pnpm check` **39/39**；`check-orphan-bundles` 10 项（含新静态防线）；负对照：去掉「实体在位」判据 ⇒ 2 项红。

## 升级注意

- 升级后重新安装一次 `@kkutysllb/dsh-git-panel`，此后**重启不再消失**。
- v0.6.28 / v0.6.29 用户建议直接升到本版（0.6.29 已含终端权限、持久终端 entry、两个子智能体、锚点归一四处修复）。
- 又及：另一个仍在退役名单的现行名是 `@kkutysllb/dsh-terminal`——那是**有意的产品级退役**（终端交回上游原生），同样会在每次启动被三清；若你希望「装了就留」，说一声我把口径改成「只退役一次」。
