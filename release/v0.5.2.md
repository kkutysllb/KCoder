# KCoder v0.5.2

> 发布日期：2026-09-01 · 上游基线：deepseek-harness 0.1.2-alpha.3 (dd6322d6)

## 修复

- **内置插件不可更新，根因修复（本版主题）**：随包分发的自有插件（dsh-skills-bundle / dsh-language-bundle / @kkutysllb/dsh-git-panel / dsh-stats-panel / @kkutysllb/dsh-terminal / @kkutysllb/dsh-file-attach / dsh-file-review-kcoder / dsh-coding-sidebar）与预置插件（dsh-context）此前无法独立更新——即便经 `dsh plugin add` 从 npm 装上新版，下次 KCoder 启动时物化层按「版本不一致即覆盖」把实体打回随包旧版，安装写入的依赖声明也被当作残留接线摘除；插件页对内置插件亦只有禁用的「卸载」按钮，无更新入口。结果是插件每次迭代都只能随桌面端发版。本版起内置插件与用户插件走同一更新通道：**插件发布 npm 新版本，用户在插件页点「更新」即达，无需等待 KCoder 发版**。三层修复：
  - **物化让位（永不降级）**：随包副本只在实体缺失/损坏/随包版本更高时落盘；本机已是更高的 registry 版本（用户更新过）则保留。应用发版携带更高随包版本时仍照常覆盖升级——本机实体与随包产物两端取其新。
  - **依赖声明保留**：实体已被 registry 新版顶替的 bundle，其 dependencies 声明不再被清理，避免 pnpm 依赖图与磁盘漂移（否则后续 install 可能把实体当 extraneous 清掉，内置功能缺实体即崩）。
  - **更新入口**：插件页已安装表操作位单按钮互换——检出 npm 新版显示「更新」，无新版回落「卸载」（内置插件保持禁卸载）。更新经统一入口按包属选路：内置层走 `dsh plugin add <pkg>@latest`（物化 bundle 不在 dependencies，pnpm update 无从谈起），用户插件维持 `update --latest`；更新前后实装版本对比入 heal 日志，假成功当场现形。
- **内置清单补漏**：dsh-stats-panel 与 @kkutysllb/dsh-file-attach 此前漏列内置清单，在插件页被误标「用户安装」且可卸载（卸掉后重启又随包复活），本版归位为内置。

## 内部维护

- 插件更新统一入口 updatePlugin（主进程按包属选路）+ `add@latest` 实装追踪；InstalledPlugin 契约新增 updatable 字段；插件页内置清单改由物化表（MATERIALIZED_BUNDLES）+ 引擎层 + 预置清单派生，消除双清单漂移。

## 升级注意

- 无需手动操作：升级后打开插件页，`@kkutysllb/dsh-terminal` 等即显示「1.0.0 → 1.0.1」与「更新」按钮，点击更新并重启引擎生效。
- 引擎层（@deepseek-ai/dsh-base / @deepseek-ai/dsh-web-app）与内置运行时整体版本耦合，继续不开放单独更新，随 KCoder 发版整包升级。
- 本机 pnpm 走镜像源（如 npmmirror）时，刚发布的插件版本可能尚未同步：「更新」显示成功但版本未变属镜像滞后，稍后重试即可（heal 日志会标注「版本未变！」）。
