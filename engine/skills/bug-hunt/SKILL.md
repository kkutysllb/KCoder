# Bug Hunt

复现并定位问题，给出最小修复和验证路径。

## 流程

1. **复现** — 用最小步骤稳定复现问题；记录输入、环境、实际 vs 预期行为。无法复现时先缩小触发条件，不要猜测。
2. **定位** — 二分法缩小范围：git bisect（回归）、日志/断点（运行时）、数据流追踪（逻辑）。每一步必须有证据支撑。
3. **最小修复** — 只改根因，不顺手重构；修复应与 bug 一一对应。
4. **验证路径** — 给出可重复的验证方式：回归测试、复现脚本或手工步骤，并实际运行确认。

## 原则

- 先证据，后假设；禁止"应该是这里的问题"式修复。
- 修复前后各跑一次验证，对比结果。
- 若根因在范围之外，如实报告并给出临时缓解方案。
