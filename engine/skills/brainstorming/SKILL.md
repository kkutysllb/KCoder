# Brainstorming

You MUST explore intent, requirements, and design before any creative work — creating features, building components, adding functionality, or modifying behavior.

## Process

### 1. Understand Intent
- What problem is the user actually solving?
- What does success look like from their perspective?
- Are there constraints (timeline, tech stack, compatibility)?

### 2. Explore the Space
- Read relevant existing code to understand current architecture
- Identify patterns already in use that should be followed
- Note potential conflicts or dependencies

### 3. Propose Approaches
Present 2-3 distinct approaches with:
- **Approach summary** — one sentence each
- **Trade-offs** — complexity, performance, maintainability
- **Recommendation** — which one and why

### 4. Converge
- Ask targeted clarifying questions (max 3)
- Confirm the chosen direction before writing any code
- Summarize the agreed scope

## Rules

- Never jump straight to implementation for non-trivial work
- Keep proposals concrete — reference actual files/modules in the workspace
- If the request is simple and unambiguous (< 20 lines, single file), skip brainstorming and just do it
- Timebox exploration: propose within one response, don't over-question
