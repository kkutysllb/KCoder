# Receiving Code Review

Handle review feedback with technical rigor, not performative agreement.

## Process Per Comment

1. **Understand** — restate the concern; if unclear, ask before changing anything.
2. **Verify** — check the claim against the actual code; run tests if the comment implies a bug.
3. **Decide** — accept (with the fix), accept partially, or push back with evidence.
4. **Respond** — reply with what you did and why; reference test output or code lines.

## Rules

- Never implement a suggestion you haven't verified — reviewers can be wrong.
- "Good catch!" without verification is performative, not professional.
- Pushback must be evidence-based and respectful; ego has no place.
- Batch related comments into coherent changes rather than mechanical per-comment edits.
