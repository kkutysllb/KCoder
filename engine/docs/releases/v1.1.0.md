# Qiongqi Engine v1.1.0

Release date: 2026-07-26.

Release commit: `76ddc88a83453a1e1f7be7bc8095f23259091183`; annotated tag: `v1.1.0`.

## Governed graph execution

- Added immutable `GraphRevision` publication with canonical digest and pinned run identity.
- Added durable work-graph events for actual node, edge, attempt, child, route, budget, approval, resource, and circuit activity.
- Added deterministic non-model node traversal while keeping `evented_v2` as the orchestration plane and Kernel as the isolated Agent execution plane.
- Added public `publishGraph`, governed `start`, `inspect`, `resolveCheckpoint`, `setGraphCircuit`, and `recordCost` facade methods.

## Production controls

- Human approvals now use durable checkpoints, one resume edge, graph-revision validation, expiration, and single-use tokens.
- Resource claims support read/write modes, wait/skip/escalate conflicts, lease renewal, and mandatory write fences.
- Graph circuits support `running`, `report_only`, `paused`, and `retired`; automatic evaluation only escalates, while manual recovery is audited.
- Evidence-based graph readiness is aggregated into `/ready` as `draft`, `observe`, `assisted`, or `autonomous`.

## Model neutrality and continuity

- Task model policy is durable and revisioned; graph nodes can reference independent versioned model policies.
- Model, usage, trace, and cost records carry graph correlation without exposing prompts or credentials.
- Core package dependencies no longer bind orchestration to adapter-tools or services back to loop.
- No provider or model ID, including `deepseek-chat`, is an engine default. Downstream products may configure and switch among arbitrary authorized profiles.

## Live streaming and ROI

- Existing durable `streamId + seq` streaming, cursor replay, subscriber ack, and private-reasoning defaults remain supported.
- Cost and value updates publish live `roi.snapshot` events with optional graph/node/edge attribution.
- Graph snapshots include fan-out, retry amplification, suppressed physical attempts, avoided cost, and executed critical-path latency.
- Business ROI remains evidence-based and separate from engine efficiency.

## Reliability and build

- Preserved durable model/tool duplicate suppression, uncertain-effect verification, context checkpoints, long-task progress, task-shared memory, Agent-private memory, cancellation, and completion outbox behavior.
- Parent budget reservations now settle against actual child usage.
- Removed the package dependency cycle and made clean builds fail on every compiler error.

## Upgrade notes

- New work should publish a graph revision and pass `graphRef` to `start()`.
- Calling `start()` without `graphRef` remains available only for v1.0 compatibility.
- Incomplete v1.0 runs cannot be converted in place. Drain them on compatibility workers or cancel and restart with a new graph run.
- PostgreSQL is required for multi-instance production. Apply additive v1.1 schema before deploying workers.
- Do not roll v1.0 binaries onto active v1.1 graph runs. See [the migration guide](../migrations/engine-v1.1.md).

## Verification

The release gate covers SQLite and PostgreSQL storage probes, workspace typecheck, fast and full test suites, strict clean build of 18 packages, evented A2A verification, release-version/compatibility tests, and whitespace validation. No `npm publish` is performed by this repository release procedure.

## Deferred P2 scope

Graph analysis, deterministic simulation, incident replay, and graph-revision canary rollout were intentionally excluded from v1.1.0. They are follow-up engine capabilities, not incomplete v1.1 release requirements.
