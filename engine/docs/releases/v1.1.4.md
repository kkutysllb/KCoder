# QiongQi Engine v1.1.4

Release date: 2026-07-28

v1.1.4 is a security and log-quality patch for the model compatibility adapter. It preserves all v1.1.3 public contracts, durable state, governed graph execution, Kernel streaming, and ROI behavior.

## User outcomes

- Valid OpenAI-compatible assistant messages containing `tool_calls` with omitted `content` no longer trigger `[diagnoseEmptyContent]`.
- Empty-message diagnostics are role-aware and continue to report genuinely invalid system, user, tool, or assistant message shapes.
- `diagnoseEmptyContent` and provider-rejection diagnostics are metadata-only. They may report message index/role, content state/type/length, tool-call count, status, message count, and request body keys.
- Diagnostics never include system prompts, user content, reasoning, tool arguments, tool results, provider error bodies, complete requests, or credentials.
- Diagnostic endpoint URLs remove userinfo, query parameters, and fragments before reaching stderr.

## Upgrade guidance

Upgrade every v1.1.3 deployment whose stderr is collected, retained, or forwarded to a central logging service. Existing logs produced by v1.1.3 may already contain request content and should be handled under the operator's retention and incident-response policy.

No database, graph, dispatch, checkpoint, ledger, stream, HTTP, or model-profile migration is required. v1.1.4 can replace v1.1.3 through a normal rolling restart.

## Verification

Regression tests exercise both the original false-positive path and HTTP 400 provider rejection with unique sentinel values in system/user content, reasoning, tool arguments, tool results, provider error text, and endpoint query credentials. The release gate additionally runs recursive typecheck, fast and full tests, clean build, native SQLite recovery, local Docker PostgreSQL engine verification, evented A2A verification, and whitespace checks.
