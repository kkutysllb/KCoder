# QiongQi Engine v1.1.3

Release date: 2026-07-28

v1.1.3 closes four production gaps in v1.1.2: graph policy references now survive the supported compiler, durable Agent dispatch is recovered from authoritative facts instead of trusting outbox context, the official HTTP/Turn surface can directly operate a governed `DurableEngine`, and production `kernel_v3` now publishes genuine assistant deltas before provider completion. QiongQi remains engine-only, product-neutral, and model-neutral.

## User outcomes

- All nine public AgentGraph node kinds accept `nodePolicyRef`; edges accept `edgePolicyRef`. Compilation preserves them and includes them in `graphDigest`.
- Changing an edge policy changes the revision digest but not the stable logical edge ID.
- New Agent dispatch intents use `schemaVersion: 3` and carry `threadId`, `turnId`, `workspaceKey`, and optional `nodePolicyRef` alongside model and execution policy references.
- Recovery workers still read schema v1/v2 work. Before Kernel execution they load the same-ID root EngineRun, GraphRun, pinned GraphRevision, and prepared AgentRun, then hydrate the authoritative context.
- Forged scope, workspace, graph digest, node, AgentRun identity, `nodePolicyRef`, model policy, or execution policy fails before prompt resolution or model/tool execution.
- `StartTurnRequest.governedExecution` is a strict, durable entry point for explicit `TaskScope`, graph revision, budget limits, and model selection policy.
- Turn↔GraphRun binding is immutable and replay-safe. If the process crashes after `DurableEngine.start()` but before the Turn binding is written, recovery finds the exact scope/thread/turn GraphRun instead of starting a duplicate.
- The optional HTTP binding exposes graph publication, run inspection, serial/parallel dispatch, Kernel completion, resume, cancellation, and durable stream operations. It requires one complete `{ engine, store }` pair and contains no product business rules.
- Governed interrupt cancels DurableEngine before aborting the user-visible Turn. GraphRun remains the fact source; completed/failed/aborted projection is idempotent.
- Production `kernel_v3` assigns a stable proposal identity before reading the first provider chunk and persists assistant deltas immediately for live thread SSE and sequence replay.
- Delta item IDs match final Kernel materialization IDs, so multiple chunks converge to one completed assistant item. Separate physical attempts remain isolated and ledger replay emits no duplicate delta.
- Provider usage remains exactly-once after durable proposal commit; real-time durable cost/value and ROI events are not estimated from text chunks.

The v1.1.2 durable parallel/join, duplicate suppression, context compaction, long-task checkpoints, task/Agent memory isolation, per-turn skill/tool/output gates, persisted Kernel budgets, and live branch ROI remain supported.

## Public HTTP entry

Products may inject their configured engine without adapting internal stores:

```ts
const runtime = await createAgent({
  ...options,
  governedEngine: { engine, store }
})
```

A governed Turn request is explicit and model-neutral:

```json
{
  "prompt": "Build the report",
  "governedExecution": {
    "scope": { "ownerId": "owner", "workspaceId": "workspace", "taskId": "task-42" },
    "graphRef": { "graphId": "report", "revision": 7 },
    "budgetLimits": {
      "stepsUsed": 100,
      "toolCallsUsed": 40,
      "inputTokens": 200000,
      "outputTokens": 40000,
      "costUsd": 25
    },
    "modelPolicy": {
      "authorizedProfileIds": ["primary", "fallback"],
      "preferredProfileId": "primary"
    }
  }
}
```

The engine does not infer task identity from thread ID and does not add a provider or model fallback.

## Compatibility and rollout

- v1.1.3 readers accept dispatch schema v1, v2, and v3; v1.1.3 writers emit only schema v3.
- Upgrade workers before enabling v1.1.3 writers. Older workers must not claim schema-v3 work.
- Existing immutable graph revisions and in-flight schema-v1/v2 dispatches are not rewritten. Drain them with v1.1.3 workers or cancel them durably.
- A v1.1.2 client may continue using ordinary Turns and direct DurableEngine APIs. `governedExecution` and the lifecycle routes are additive.
- Runtime composition without `governedEngine` preserves ordinary Turn execution and returns HTTP 503 for governed operations.
- PostgreSQL remains required for multi-instance production. SQLite remains suitable for development, conformance, and single-process reconstruction.

See [engine-v1.1.md](../migrations/engine-v1.1.md) for detailed drain and rollback rules.
