# Qiongqi Engine v1.1.1

Release date: 2026-07-27

v1.1.1 fixes a production-blocking governed-run consistency defect in v1.1.0. It keeps Qiongqi engine-only and model-neutral: downstream callers may register any provider, authorize multiple immutable model profiles, and switch task policy without an engine default.

## User outcomes

- Governed starts now create `GraphRunRecord` and root `EngineRunRecord` with the same ID and version in one transaction, so Kernel dispatch always has a durable parent.
- Dispatch is prepare-first: stable AgentRun/KernelRun identity, parent reservation, and `agent_execution_requested` intent commit before execution. Local and remote workers use the same claimed, renewable, fenced handler.
- Root budgets are cumulative across sequential and concurrent children: settled actual usage plus active requested reservations plus the new request cannot exceed caller limits.
- Crash recovery reuses the original prepared identity, reservation, and intent. Duplicate completion does not advance the root version or double-count usage.
- Root completion, cancellation, checkpoints, circuits, and governance operations keep both projections aligned.

Existing v1 features remain covered: model/tool duplicate suppression, structured context compaction, long-task checkpoints, task/Agent memory isolation, durable real-time streaming, subscriber replay/ack, live ROI, and model-neutral routing.

## Required caller change

Every governed `start()` must provide root limits:

```ts
const started = await engine.start({
  scope,
  threadId,
  turnId,
  workspaceKey,
  prompt,
  modelPolicy,
  graphRef: { graphId: revision.graphId, revision: revision.revision },
  budgetLimits: {
    stepsUsed: 100,
    toolCallsUsed: 40,
    inputTokens: 200_000,
    outputTokens: 40_000,
    costUsd: 25
  }
})
```

`start()` returns after the root aggregate and first durable dispatch preparation commit. It does not wait for model completion; consume `started.streamId` for model delta, tool progress, checkpoint, usage, ROI, and outcome events.

The compatibility `start()` shape without `graphRef` remains unchanged and does not accept `budgetLimits`.

## v1.1.0 graph-only migration

Affected v1.1.0 deployments may contain a governed GraphRun without a root EngineRun. Loaders fail closed with `ROOT_RUN_AGGREGATE_INCOMPLETE`; they never auto-repair or invent limits.

After stopping claims and reviewing durable usage, explicitly authorize:

```ts
await engine.migrateGraphOnlyRun({ runId, budgetLimits })
```

Migration validates the pinned revision, creates the missing projection, advances both records together, and appends `root_run_repaired`. A terminal run is repaired for audit consistency but is never dispatched again. See [engine-v1.1.md](../migrations/engine-v1.1.md).

## Operational requirements

- PostgreSQL is required for multi-instance production. Reservation admission must lock the parent row while checking cumulative usage.
- Workers must renew claims through `renewWorkClaim()` before TTL expiry. Renewal failure stops commits; a higher fence may recover the original intent.
- Treat `ROOT_RUN_AGGREGATE_INCOMPLETE`, `ROOT_RUN_AGGREGATE_DIVERGED`, and `ROOT_RUN_BUDGET_MISSING` as operator-review errors, not blind retries.
- Configure model profiles and policy explicitly. There is no default provider, model ID, or `deepseek-chat` fallback.
