## 简介
本技术文档聚焦于KCoder的数据迁移系统，围绕迁移框架的设计原理与实现进行系统化说明。内容涵盖版本管理、增量更新、回滚机制；迁移脚本编写规范（SQL模板、参数化查询、错误处理）；执行流程（迁移检测、依赖解析、事务控制）；数据兼容性（向后兼容、向前兼容、转换规则）；迁移过程中的数据验证（完整性检查、一致性验证、异常处理）；工具使用方式（命令行接口、API调用、批量操作）；以及失败处理策略与恢复方案。

## 项目结构
仓库采用多包工作区组织，迁移相关能力主要位于 engine 子工程：
- scripts 目录包含构建、准备、校验与迁移相关的可执行脚本，其中 migrate-packages.mjs、migrate-tests.mjs、prepare-sqlite.mjs 等与数据迁移直接相关。
- tests 目录包含大量测试用例，覆盖任务状态存储、运行态内核、事件总线、持久化与缓存、工具运行时等多个子系统，为迁移的稳定性与兼容性提供保障。

## 核心组件
- 迁移编排器（migrate-packages.mjs）
  - 负责发现待执行的迁移任务、解析依赖关系、按顺序执行并记录结果。
  - 支持增量模式，仅对未完成的迁移进行变更。
  - 集成事务边界，确保单条迁移的原子性。
- 测试迁移适配层（migrate-tests.mjs）
  - 将测试套件中的迁移步骤映射到统一执行模型，便于在CI中验证迁移正确性。
- SQLite 初始化与准备（prepare-sqlite.mjs）
  - 提供数据库连接、表结构初始化、索引创建等基础能力，供迁移脚本复用。
- 迁移脚本编写规范
  - SQL模板：以声明式描述目标状态，避免硬编码环境差异。
  - 参数化查询：通过占位符注入动态值，防止注入风险。
  - 错误处理：捕获并上报具体错误上下文，便于定位问题。
- 执行流程
  - 迁移检测：对比当前版本与期望版本，计算差集。
  - 依赖解析：根据声明的依赖图确定执行顺序。
  - 事务控制：每条迁移在一个事务内执行，失败即回滚。
- 数据兼容性
  - 向后兼容：旧客户端可继续读取新结构。
  - 向前兼容：新客户端可容忍旧结构缺失字段。
  - 转换规则：定义字段映射、类型升级、默认值填充等。
- 数据验证
  - 完整性检查：约束外键、唯一性、非空等。
  - 一致性验证：跨表统计、聚合校验、抽样比对。
  - 异常处理：记录异常详情、触发告警、进入修复流程。
- 工具使用
  - 命令行接口：提供一键执行、预览、回滚、报告生成等命令。
  - API调用：暴露REST或SDK方法，用于集成到流水线。
  - 批量操作：支持并行迁移、分片执行、断点续跑。
- 失败处理与恢复
  - 幂等设计：重复执行不产生副作用。
  - 快照与回滚：迁移前自动快照，失败后快速恢复。
  - 补偿脚本：针对不可逆变更提供补偿逻辑。

### 执行流程（迁移检测、依赖解析、事务控制）
- 迁移检测
  - 读取已执行版本与期望版本，计算差集。
  - 支持增量模式，仅对未完成的迁移进行变更。
- 依赖解析
  - 基于声明的依赖图进行拓扑排序，确保无环。
  - 识别阻塞项，提前失败并提示。
- 事务控制
  - 每条迁移在一个事务内执行，失败即回滚。
  - 提交后记录执行元数据，便于审计与追踪。
- 可视化

```mermaid
flowchart TD
Detect["迁移检测"] --> Diff["计算差集"]
Diff --> Resolve["依赖解析"]
Resolve --> Sort["拓扑排序"]
Sort --> Execute["逐条执行"]
Execute --> TxBegin["开启事务"]
TxBegin --> Apply["应用DDL/DML"]
Apply --> Validate["运行验证规则"]
Validate --> Success{"验证通过?"}
Success --> |是| Commit["提交事务"]
Success --> |否| Rollback["回滚事务"]
Commit --> Record["记录元数据"]
Rollback --> Report["记录错误"]
Record --> Done(["完成"])
Report --> Done
```

### 数据兼容性处理
- 向后兼容
  - 新增字段设置默认值，旧客户端忽略未知字段。
  - 保留旧表名或视图，逐步废弃。
- 向前兼容
  - 新客户端读取旧结构时，缺失字段提供默认值或降级逻辑。
  - 版本探测与条件分支，避免强依赖新特性。
- 数据转换规则
  - 字段映射：旧字段到新字段的映射与合并。
  - 类型升级：如字符串到枚举、数值精度提升。
  - 清洗与规范化：去重、格式标准化、空值处理。

### 工具使用方法
- 命令行接口
  - 执行迁移：一键运行所有待执行迁移。
  - 预览模式：显示将要执行的变更，不实际落盘。
  - 回滚：回滚最近一次迁移或指定版本。
  - 报告：生成执行报告与审计日志。
- API调用
  - REST端点：提供迁移状态查询、触发迁移、获取报告。
  - SDK：在应用中调用迁移服务，集成到部署流程。
- 批量操作
  - 并行迁移：按依赖分组并行执行。
  - 分片执行：大数据量分片处理，降低锁竞争。
  - 断点续跑：从上次失败位置继续执行。
- 可视化

```mermaid
sequenceDiagram
participant Dev as "开发者"
participant CLI as "命令行接口"
participant API as "API服务"
participant Orchestrator as "迁移编排器"
participant Store as "持久化存储"
Dev->>CLI : 执行迁移命令
CLI->>API : 触发迁移
API->>Orchestrator : 启动迁移
Orchestrator->>Store : 读取版本与元数据
Orchestrator->>Store : 执行DDL/DML
Store-->>Orchestrator : 返回结果
Orchestrator-->>API : 返回执行状态
API-->>CLI : 输出报告
```

### 失败处理策略与恢复方案
- 幂等设计
  - 迁移脚本具备幂等性，重复执行不会产生副作用。
- 快照与回滚
  - 迁移前自动快照，失败后快速恢复。
  - 支持选择性回滚与补偿脚本。
- 补偿逻辑
  - 针对不可逆变更提供补偿脚本，修正不一致数据。
- 可视化

```mermaid
flowchart TD
Begin(["开始"]) --> Snapshot["创建快照"]
Snapshot --> Execute["执行迁移"]
Execute --> Success{"成功?"}
Success --> |是| Release["释放资源"]
Success --> |否| Rollback["回滚到快照"]
Rollback --> Compensate["执行补偿脚本"]
Compensate --> Report["记录错误与上下文"]
Release --> End(["结束"])
Report --> End
```

## 性能考虑
- 批量化与分片：大表变更建议分批次执行，减少锁竞争与长事务。
- 索引优化：在大批量插入前临时禁用索引，完成后重建。
- 并发控制：按依赖组并行执行，避免热点冲突。
- 监控与度量：记录执行时长、影响行数、错误率，便于容量规划。
- 资源隔离：迁移与业务读写分离，避免相互影响。

## 故障排查指南
- 常见问题
  - 依赖解析失败：检查迁移声明的依赖是否形成环。
  - 事务回滚：查看错误上下文与受影响行数，确认数据一致性。
  - 验证失败：核对完整性与一致性规则，定位异常数据。
- 调试技巧
  - 启用详细日志，记录每一步执行与参数。
  - 使用预览模式验证变更范围。
  - 在隔离环境复现问题，缩小影响面。
- 恢复步骤
  - 回滚到最近稳定版本。
  - 执行补偿脚本修复不一致数据。
  - 重新运行迁移，观察报告与指标。
