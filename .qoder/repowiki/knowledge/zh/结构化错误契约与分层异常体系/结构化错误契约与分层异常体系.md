本仓库采用「HTTP 层统一错误体 + 领域层自定义 Error 子类」的分层错误处理方案，贯穿 Electron 主进程、QiongQi 引擎多包以及渲染进程。

## 1. HTTP 层：统一的 QiongqiErrorBody 契约
- engine/packages/foundation/contracts/src/errors.ts 通过 Zod 枚举 QiongqiErrorCode 定义所有受支持的错误码（如 validation_error、unauthorized、forbidden、not_found、conflict、rate_limited、turn_in_progress、internal_error、aborted 等），并导出 QiongqiErrorBody = { code, message, details? } 结构类型。
- engine/packages/http-layer/http/src/routes/runtime-error.ts 提供工厂函数 ERRORS.{unauthorized|forbidden|notFound|validation|attachmentValidation|conflict|notImplemented|unavailable|internal}，统一构造符合契约的 JSON 响应。
- engine/packages/http-layer/http/src/read-json-body.ts 在解析请求体失败时直接返回 { ok: false, response: jsonResponse({ code: 'validation_error', ... }, 400) }，保证所有 HTTP 入口的错误体一致。
- 渲染进程 app/renderer/src/services/engine-api.ts 在调用本地 HTTP API 时，对非 2xx 响应尝试读取 detail 字段并以 throw new Error(...) 抛出，使上层 hooks 能捕获到人类可读的消息。

## 2. 领域层：按职责划分的自定义 Error 子类
各业务包各自定义语义明确的 Error 类，携带额外属性供上层区分处理：
- AuthError（http-layer/http/src/auth-service.ts）：带 status 字段，用于认证相关 4xx 错误。
- UsageValidationError（engine/services/src/usage-service.ts）：固定 code = 'validation_error'，用于用量查询参数校验。
- RuntimeKernelCrash / RuntimeLeaseLost（engine/loop/src/runtime-kernel.ts）：运行时内核专用，配合租约守卫和 crash recovery 测试路径。
- ResultNormalizationError（engine/loop/src/tool-observation.ts）：工具结果规范化阶段抛出的领域错误。

这些类均继承自原生 Error，并通过 name、附加字段或 code 属性进行区分，而非使用全局单例 sentinel error。

## 3. 中间件与运行期错误传播
- RuntimeKernel 内部通过 MiddlewareChain 在 beforeRun / afterRun 钩子中收集命令与 outcome；当租约丢失时抛出 RuntimeLeaseLost，由外层捕获后转为 runOutcome 中的 reason: 'runtime_error' 并标记 retryable: true。
- 引擎测试覆盖了大量错误路径（如 tool-dispatch-errors.test.ts、runtime-kernel-crash-recovery.test.ts、runtime-middleware-governance.test.ts），表明错误被作为一等公民纳入可重放、可恢复的执行图。

## 4. Electron 主进程与渲染进程
- 主进程 app/main/engine-host.ts、settings.ts 使用 try/catch 包裹启动、设置读写等操作，遇到异常后向上抛出 new Error(...)，由 Electron 未捕获异常处理器兜底。
- 渲染进程 hooks（useAuth.ts、useChat.ts）在调用 engine-api.ts 后以 .catch(() => ...) 或 try/catch 捕获错误，将消息展示给 UI。

## 5. 开发者约定
- 对外 HTTP 接口：一律通过 ERRORS.* 工厂或自行构造 { code, message, details? } 对象返回，禁止裸字符串。
- 领域逻辑：需要跨层传递语义化错误的地方，定义新的 extends Error 子类并带上必要字段（如 status、code）。
- HTTP 输入校验：优先使用 Zod 校验并在 catch 中映射为 validation_error 错误体。
- UI 层：只消费 message 文本进行提示，不依赖具体 Error 类名。
