项目采用双仓库合并布局：`engine/` 为 vendored 的 QiongQi monorepo（pnpm workspace），按 `packages/{adapters,capabilities,cli-layer,delegation-layer,domain-layer,engine,foundation,http-layer,infrastructure,ports-layer,presets}` 分层组织；`app/` 是 Electron + Vite 前端。

- Main 进程入口 `app/main/index.ts` 在 `app.whenReady()` 中调用 `startEngine()` 动态 import `@qiongqi/preset-coding` 与 `@qiongqi/http`，创建 coding agent 并启动仅监听 `127.0.0.1` 的 HTTP server，随后用端口+token 参数打开 BrowserWindow。
- 渲染进程通过 URL query (`enginePort`, `engineToken`) 获取 engine 地址，由 `renderer/src/services/engine-api.ts` 发起 REST 调用；状态集中在 `renderer/src/stores/app-store.ts`（Zustand）。
- 安全边界由 `app/preload/index.ts` 通过 `contextBridge.exposeInMainWorld('kcoder', ...)` 暴露最小 IPC API（window 控制、设置保存、PTY terminal），白名单校验 channel 名后再转发到 main 的 `terminal.ts` / `settings.ts` 等模块。
- 构建管线：`electron-vite.config.ts` 将 main、preload 输出为 ESM（`[name].mjs`），renderer 使用 `@vitejs/plugin-react` 与 Tailwind；打包由 `electron-builder.yml` 驱动。
- 依赖方向单向：`app` → `@qiongqi/*`（workspace 协议引用 engine 下包），engine 内部自底向上依赖 `foundation/contracts` → `domain-layer/domain` → `engine/loop` + `engine/services` → `presets/preset-coding`，HTTP 层作为对外出口。
