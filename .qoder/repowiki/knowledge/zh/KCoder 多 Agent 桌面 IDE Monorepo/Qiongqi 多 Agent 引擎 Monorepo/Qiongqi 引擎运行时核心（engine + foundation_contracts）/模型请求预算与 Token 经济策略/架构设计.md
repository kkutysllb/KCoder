本模块由三个职责互补的纯函数文件组成，均无副作用，依赖方向单向指向 `@qiongqi/contracts`、`@qiongqi/ports`、`@qiongqi/domain` 以及 loop 内部估算器：
- `model-request-budget.ts`：入口 `applyModelRequestInputBudget` 基于 `ContextEstimator` + `estimateModelRequestInputTokens` 计算固定开销后，从历史末尾向前挑选 TurnItem，对超出预算的项通过 `clipItemForBudget` 按 kind 分支裁剪文本/JSON，并带 CLIP_SAFETY_RATIO(0.85) 与 MIN_CLIPPED_ITEM_TOKENS(24) 安全阈值；最多迭代 4 次按比例回退。
- `token-economy.ts`：以 `TokenEconomyConfig`（默认关闭）为开关，`applyTokenEconomyToRequest` 并行做三件事——追加 `TOKEN_ECONOMY_INSTRUCTION`、`compactToolSpec` 压缩 tool description/inputSchema、`compactHistoryItem` 压缩 history；其中 `compactToolOutput` 按 toolName 分派到 bash/read/grep/find/ls 专用压缩器，其余走 `compactGenericValue` 递归剪枝数组与对象，所有可写文本先经 `withProtectedSegments` 用 `PROTECTED_PATTERNS`（代码块、URL、路径、驼峰常量等）保护后再执行 `compressProse` 去填充词与冗余标点。
- `continuation-policy.ts`：仅作为遗留命名空间，把 `decideLoopContinuation`（定义于 `loop-policy.ts`）重新导出为 `decideContinuation`，并暴露 `ContinuationDecision` 联合类型及 `isDispatchDecision` 守卫，供经典 `TurnOrchestrator` 继续使用。
三者共同构成“估算 → 裁剪/压缩 → 决策”的预处理管线，被上层 loop 编排器在构造最终 request 前依次调用。
