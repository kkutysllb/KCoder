模块以 `http/src/index.ts` 作为包入口，按职责拆分为三层：
- 传输/分发层：`http-server.ts` 定义平台无关的 `dispatchRequest`，负责路由匹配、OpenTelemetry span 注入、access log 回调；`node-http-server.ts` 基于 Node `http.Server` 将 `IncomingMessage`/`ServerResponse` 桥接为 Fetch `Request`/`Response`，并处理 CORS 预检与多 Set-Cookie。
- 路由层：`router.ts` 实现极简 `Router`（仅支持 `:param` 占位符，按注册顺序匹配），`routes/index.ts` 通过 `buildRouter(ServerRuntime)` 集中注册所有 `/api/*`、`/v1/*`、`/.well-known/*`、`/a2a/*` 端点，并按需调用各子路由文件中的 handler。
- 领域路由组：`routes/` 下每个文件对应一个资源域（threads、turns、sessions、memory、skills、attachments、artifacts、uploads、review、approvals、user-inputs、events、health、runtime-info、usage、agent-card、kworks-compat、default-workspace、workspace、server-runtime、runtime-error、a2a、skill-drafts），handler 只依赖 `ServerRuntime` 聚合接口（见 `routes/server-runtime.ts`），不直接耦合具体服务实现。
- 横切能力：`auth.ts`/`auth-service.ts`/`auth-store.ts` 提供 Bearer/Cookie 双通道鉴权与用户会话存储；`response.ts` 统一 `JsonResponse` 结构；`sse.ts` 封装 SSE 流式响应；`telemetry.ts` 暴露 OpenTelemetry 门面；`read-json-body.ts` 解析 JSON body；`finance-credentials.ts`、`kworks-*`、`qiongqi-config-store.ts`、`user-scoped-model-client.ts`、`a2a-task-*`、`http-peer-transport.ts`、`review-service.ts` 等提供特定协议/后端适配。
依赖方向：路由 → 领域 handler → `ServerRuntime` 聚合接口 → 外部 workspace 包（`@qiongqi/services`、`@qiongqi/ports`、`@qiongqi/contracts`、`@qiongqi/memory`、`@qiongqi/skills`、`@qiongqi/adapter-tools`、`@qiongqi/attachments` 等），本包自身不持有业务状态。
