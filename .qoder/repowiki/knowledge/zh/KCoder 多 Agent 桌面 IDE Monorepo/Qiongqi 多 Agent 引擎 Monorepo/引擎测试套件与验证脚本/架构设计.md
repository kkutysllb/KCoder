本模块由两部分组成：
- `engine/tests/`：基于 Jest（通过 `describe`/`it`）的测试集，按被测能力分文件组织（如 `loop-runner.test.ts`、`http-server.test.ts`、`runtime-kernel-e2e.test.ts` 等），并通过共享夹具隔离外部依赖。
- `engine/scripts/`：Node ESM 脚本，其中 `build.mjs` 是顶层构建编排器，显式声明 18 个包的拓扑构建顺序以绕过 `{services, delegation, adapter-tools, loop}` 强连通分量中的循环类型引用；其余 `verify-*.mjs` 为端到端验证脚本（崩溃恢复、SQLite、事件化 A2A 等），直接调用 `@qiongqi/http` 暴露的 `createAgent`/`createHttpServer` 启动真实进程。

测试基础设施集中在两个可复用的 harness：
- `loop-test-harness.ts`：构造 `TurnOrchestrator` + `TurnService` + `ThreadService` + `InMemory*` 存储/总线/审批门的全量内存运行时，供绝大多数单元/集成测试复用。
- `http-server-test-harness.ts`：在 harness 之上再组装 `@qiongqi/http` 的 `buildRouter`/`AuthService`/`KWorksUserDataStore`，用于 HTTP 层测试。

测试数据通过 `fixtures/kernel-governance/*.json` 注入到治理相关用例。`global.d.ts` 为根级测试补充 `better-sqlite3` 的类型声明，避免跨包类型不可见问题。
