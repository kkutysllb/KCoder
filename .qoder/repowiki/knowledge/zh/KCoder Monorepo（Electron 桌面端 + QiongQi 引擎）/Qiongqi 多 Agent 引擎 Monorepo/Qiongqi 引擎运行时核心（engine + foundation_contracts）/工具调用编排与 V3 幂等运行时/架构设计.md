本模块由三个职责分明的文件组成：
- `tool-call-coordinator.ts` 是对外入口 `ToolCallCoordinator`，负责从模型侧接收 `ToolCallLike[]`，按 turn 维度建立 `ToolStormBreaker` 做重复/风暴抑制，用 `isParallelSafeToolCall` 把只读内置工具聚成最多 `MAX_PARALLEL_TOOL_CALLS` 的批次通过 `Promise.allSettled` 并发执行，非安全调用则串行；每次结果经 `persistToolCallResult` 写入 TurnService 并触发 `afterToolResultPersisted`（如 CREATE_PLAN 工具的 checklist 同步）。
- `tool-runtime-v3.ts` 暴露 `ToolRuntimeV3.execute`，以 `idempotencyKey(identity, callId)` 为粒度在进程内 `inFlight` Map 去重，并在 `EffectCommitCoordinator` 协助下完成 prepare → recordPrepared → execute → commit 四阶段流程，支持 `crashPoint` 钩子与 `crashAfterExecute` 注入点，返回 `{ state, result?, observation?, replayed, outcome? }` 以便上层恢复或挂起。
- `tool-dispatch-errors.ts` 集中定义 `isRecoverableToolDispatchError`，协调器捕获后将其降级为带 `tool_dispatch_rejected` code 的 `tool_result` item，避免整轮崩溃。
依赖方向：协调器组合 `ToolRuntimeV3`（可选）、`InflightTracker`、`ToolStormBreaker`、`tool-observation`、`effect-commit.js`，向上仅暴露 `dispatch` / `executeToolCall` 等接口，向下通过 `@qiongqi/ports` 的 `ToolHost`、`ApprovalGate`、`UserInputGate`、`TurnService`、`RuntimeEventRecorder` 等端口与外部交互。
