- 服务类通过构造函数注入依赖（ThreadStore/SessionStore/IdGenerator/RuntimeEventRecorder 等），而非全局单例或 import 具体实现，便于测试替换。
- 写操作采用 per-thread 的 Promise 队列模式：先取 `this.xxxQueues.get(threadId) ?? Promise.resolve()`，再 `.then(async () => { ... })` 追加新任务，finally 中清理 guard，保证同一 thread 的写入串行化。
- 持久化后统一通过 `events.record({ kind, ...payload })` 发布语义事件，事件名采用 snake_case（如 `thread_created`、`turn_started`、`item_created`、`compaction_completed`）。
- 时间戳由注入的 `nowIso: () => string` 提供，禁止在业务方法内直接调用 `new Date().toISOString()`，以保证可测试性与一致性。
- 对外暴露的类型以 `Options` / `Deps` 后缀命名（如 `ThreadServiceOptions`、`TurnServiceDeps`），并将可选字段集中放在 options 对象中传入。
- 错误信息采用模板字符串描述上下文（如 ``thread not found: ${id}``、``invalid GUI plan relative path: ${path}``），并抛出普通 `Error` 或自定义 `UsageValidationError`。
