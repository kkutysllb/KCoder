本模块由三个职责独立的纯函数文件组成，均不持有状态，仅依赖 `@qiongqi/contracts` 中的 `ModelProposal` 与 `TaskStateV1` 类型：
- `proposal-classifier.ts`：核心入口 `classifyProposal` 按优先级顺序匹配 `stopClass`、`integrity` 标志、工具调用数量、文本长度与关键词，将提案归入 `final_text` / `tool_intents` / `empty` / `length_limited` / `safety_or_refusal` / `protocol_error` / `context_discontinuity` / `nonterminal_action` 八类之一；辅助函数 `isContextDiscontinuityText`、`isNonterminalActionText`、`looksTerminal`、`includesAny` 通过 NFKC 规范化 + 正则去空白标点后做中英双语子串匹配。
- `proposal-materializer.ts`：`materializableProposalContent` 过滤掉存在协议泄漏或工具调用畸形时的 reasoning/text，仅返回非空字段，作为上层渲染层的数据投影。
- `review-prompt.ts`：导出常量 `QIONGQI_REVIEW_PROMPT`，以字符串数组拼接形式定义 LLM 代码审查的系统提示，约定 JSON 输出 schema（findings、priority、confidenceScore、codeLocation 等）。
依赖方向单向：本模块被 loop 上层消费，自身不反向引用 loop 内部其它模块。
