本仓库采用「契约层定义 + HTTP 层统一响应 + 运行时中间件钩子」三层架构实现跨进程（Electron 渲染层 ↔ QiongQi 引擎）的错误处理，核心约定如下：

## 1. 统一的 API 错误契约
- `@qiongqi/contracts` 包通过 Zod 枚举 `QiongqiErrorCode` 集中声明所有可返回的 code（如 `validation_error`、`unauthorized`、`not_found`、`internal_error`、`aborted` 等），并定义 `QiongqiErrorBody = { code, message, details? }` 作为每个 HTTP/SSE 端点的标准错误体。
- `RuntimeErrorSeverity` 枚举 (`info | warning | error`) 用于标注事件级错误严重度。
- 该契约同时被 domain-layer 的 `makeErrorItem` 复用，把错误以 `kind: 'error'` 的 TurnItem 持久化到运行快照中，保证 UI 与后端对同一错误的理解一致。

## 2. HTTP 层统一错误响应器
- `@qiongqi/http` 提供 `errorResponse(body, status)` 以及预置工厂 `ERRORS.unauthorized / forbidden / notFound / validation / conflict / notImplemented / unavailable / internal`，确保所有路由抛出的业务异常都映射为 `{ code, message, details? }` 结构。
- 领域内自定义错误类（如 `AuthError`）携带 HTTP status，由上层路由捕获后转为 `QiongqiErrorBody`；HTTP 客户端侧则通过 `classifyHttpError` 将远端 code/message/details 还原回本地错误上下文。

## 3. 运行时内核的错误传播与恢复
- `RuntimeKernel.run` 在 try/catch 包裹整个执行循环，遇到未捕获异常时：
  - 调用 middleware 链的 `onError` 钩子，允许审计、上报或注入补偿命令；
  - 尝试保存失败 outcome（lease 丢失时 best-effort）；
  - 返回 `RunOutcome { status: 'failed', reason: 'runtime_error', retryable, details }`。
- 两类运行时专用 Error 子类承载特殊语义：
  - `RuntimeKernelCrash`：包装任意内部崩溃，外层 catch 后抛出其 `original`，使测试能断言原始堆栈；
  - `RuntimeLeaseLost`：分布式租约丢失信号，驱动外部重试/迁移逻辑。
- 工具分发错误通过 `isRecoverableToolDispatchError` 按 message 前缀判定是否可恢复（unknown tool / disabled by policy 等），供上层决定是否重试而非直接失败。

## 4. 设计决策与约束
- **禁止裸 throw**：对外暴露的边界（HTTP、SSE、IPC）必须产出符合 `QiongqiErrorBody` 的结构体，禁止向渲染层泄露内部堆栈。
- **code 优先于 message**：UI 状态机依据 `code` 分支，`message` 仅用于人类可读提示，`details` 承载可选诊断数据（如 Zod issues）。
- **错误即事件**：除 HTTP 响应外，引擎内部错误还以 `ErrorEvent` / `ErrorTurnItem` 形式进入事件总线与持久化流，保证回放与调试一致性。
- **中间件可观测性**：`onError` 钩子是全局唯一接入点，所有监控、告警、指标采集应在此处完成，避免在各 node handler 重复散布。
