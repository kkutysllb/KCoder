# dsh-coding-sidebar 1.0.29

> 设置通道迁移：偏好字段从 `dsh-settings` 命名空间并入 0.1.7 的 profile-config
> `/ volatile` 通道；RPC 路由与客户端契约零改动。

## 变更

### 设置命名空间 → 0.1.7 profile-config / volatile

- **config.ts**：26 个偏好字段并入 `Config` 并标记 `.volatile()`（宿主限制类
  字段保持非 volatile——它们是部署面而非用户偏好）；`prefsOf()` / `plainConfig()`
  改读活引用；schema 改由 **fork 的 `@deepseek-ai/schemastery`** 构造——stock
  版本只认 meta 标记、不产生引用，loader 会因此**静默跳过** volatile 提交
  （这是本次迁移的核心坑）。
- **index.ts**：`settings.register / describe / update` 桥接块 → `configEditor.edit`
  写路径（entry 按 `name` / `id` 双匹配，跳过 disabled 行），并补 loader /
  `volatile-update` 两处重评估门控；**RPC 路由形状与客户端契约零改动**；
  `SettingsConflictError` 本地化，删掉对 `dsh-settings` 的依赖。
- **context-types**：删 `SidebarSettingsService`，补 `configEditor` / `loader` /
  `root` 与 `volatile-update` 重载面。
- **测试**：新增 config / volatile 7 组断言（fork 引用解析、volatile 标记矩阵、
  默认值兜底）。
- **package.json**：删 `@deepseek-ai/dsh-settings`（peer/dev），加
  `@deepseek-ai/schemastery`（^3.18.3）与 `cosmokit`（peer/dev）。

## 兼容性说明

- 设置页与 wire 协议不变（路由形状零改动），客户端无需同步升级；
- 写入路径依赖 0.1.7 的 `configEditor`，本版 peer 范围**尚未**声明
  `^0.1.7-alpha.1`（由 1.0.30 补齐）——0.1.7 线的正式发布版本请用 1.0.30，
  本版保留为迁移过程版本。
