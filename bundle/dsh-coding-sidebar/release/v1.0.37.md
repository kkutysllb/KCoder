# dsh-coding-sidebar 1.0.37

> 本版两块重点：**工作流图可手动摆放**（节点级拖动 + 树形/紧凑/网格一键整理）与
> **后台任务浮动面板显示作业真实输出**（不再只在模型读过时才显示）。另有
> 「任务管理」tab 的整体升级：工作流图画布（新视图，与经典树共享同一视图模型与
> 折叠状态）、两分组折叠聚合，以及 TeamView 的 0.1.7 投影迁移修复（此前所有受支持
> 宿主上团队 tab 都是「服务缺失」空态）。

## 变更

### 工作流图（新视图，`subagent-tasks-model` + `subagent-tasks-layout` + `WorkflowGraph`）

- 会话树渲染为分层节点 + 三次贝塞尔连线的画布：**拖拽平移、滚轮缩放到光标、
  双击背景适配**，右下控制条（放大 / 缩小 / 适配）。工具条新增 **图/树切换**
  （宽屏默认图、窄屏默认树），两种模式共享同一视图模型与折叠状态。
- 节点卡：类型徽章（主代理 / 子代理 / 已完成聚合 / 待命聚合 / 占位）+ 名称 +
  底部状态条（状态点 + 状态词）；运行中节点扫过动画
  （`prefers-reduced-motion` 下关闭）；当前会话 accent 描边。
- 未水合分支渲染为**占位节点**（直接子代理计数），并同时触发一次投影读取——
  水合后自动替换为真实子树。

### 两分组折叠聚合

- 子代理按续接模式分两组：**已完成**（one-shot + 空闲）与 **待命**（continuable +
  空闲，可再次唤起）；组员数 ≥ `FOLD_MIN`（6）时折叠为单行聚合（名字行取前两个
  成员名），点击展开/收起。运行中行永不折叠。
- 取代旧的「展开更早的 N 个子代理」按时间切割（该键保留于语言包，暂未删除）。

### 注册失败必须回滚（上游 v0.22.1「接管 id 孤儿化」的同构守卫）

- **问题同构**：本仓库有两处 `for (…) disposers.push(register(…))` ——内建
  tab/viewer 注册（`src/client/builtins/index.ts`）与八个 agent 工具注册
  （`src/tools.ts`）。中途任一步抛错时，**前面已占用 id 的 disposer 随栈帧一起
  丢失**，这些 tab/工具永久无法再注册（下次激活一直 "already registered"，
  直到刷新页面）——正是上游 #770/#771 那类缺陷。
- **修法**：新增纯模块 `src/registration.ts` 的 `registerBatch()`：逐项注册并
  立刻记录 disposer；任一步失败**逆序释放**已占用项后原样抛出，使**重试真的
  能重新注册**；返回的 disposer 幂等，单个 disposer 抛错不拖住其余。两处注册
  序列都改为整批原子（tab 与 viewer 视为同一批）。
- **附带加固**：注册表的 `notify()` 抽为 `notifyIsolated()`——订阅者抛错不再
  打断"注册 + 通知"链路（否则 `tabs.set` 已生效而 disposer 未返回，同样产生
  孤儿 id），也不会跳过其后的订阅者。
- **测试**：9 条断言钉在事件日志上——LIFO 释放、幂等、失败后无残留、失败点之后
  不再尝试、**回滚后重试成功**、failed 释放事件可观测、dispose 抛错不拖累、
  void 注册安全、订阅者抛错不中断注册且 disposer 仍能释放。

### 后台任务浮动面板显示作业真实输出

- 故障：面板原先只回放 `job_output`（"模型读过什么"）。模型没读过的作业，面板
  长期停在"等待模型读取"提示——即使作业正在疯狂打印；用户点开浮动面板看不到
  具体输出。
- 修法：读**作业自己的输出环**（新增 `src/job-retained-output.ts`，走宿主注册表
  的**非消费**读 `readAt`，不触碰模型的 `job_output` 游标与 notice 状态，与上游
  `job.follow` 流读的是同一个投影）。面板取最新 256KB 窗口，越窗/`lossy` 标记
  截断；响应新增 `source: 'live' | 'model'`——`live` 时空输出就是"真的还没输出"，
  不再误报"等待模型读取"。作业记录已回收 / 注册表缺读接口时回落到原回放路径。
- **实测**：运行中作业的面板输出随作业增长（长度 42 → 126 → 216 → 306 → 426，
  行数 3 → 29，内容即作业真实 stdout），起始即包含最早保留行；无页面报错。
  单测覆盖读整圈、长输出只取最新窗口并标截断、`lossy` 标截断、空输出不标截断、
  记录回收/缺接口/无注册表一律回落 undefined。

### 轨迹图图例在窄侧栏不再竖排

- 故障：图例是一行**可收缩且不换行**的 flex，侧栏一窄，每个 chip 被压到小于内容

- 实测：默认 479px 图例 2 行、单个 chip 高 16–18px；把面板压到 **210px** 后变为
  4 行、chip 仍为 16–18px（单行），**被压扁（scrollWidth > clientWidth）的 chip
  数 = 0**，不再出现竖排文字。

### 自动整理：树形 / 紧凑 / 网格三种排布

- 控制条新增 `树形 | 紧凑 | 网格` 三枚芯片（`data-wf-mode`，`aria-pressed` 标出
  当前模式）：点任意一枚 = **清掉手动偏移 + 按该模式重排 + 重新适配**，一步把
  "子代理太多看不清"拉回一张整齐的图；模式按树根缓存，切模式/重开标签不丢。
- 纯布局新增 `TaskLayoutMode`：`tree`（层级，父居中，间距 36/64）、`compact`
  （同层级、间距 14/38）、`grid`（**按深度分行并按列网格折行**，每行至多 6 列
  ——宽扇出从一条无尽长条变成可读的块）。三种模式共用同一套连线与包围盒计算，
  手动偏移在任一模式下都仍然生效。
- **实测**（同一棵树，面板 467×819）：内容盒 tree 1184×196 / compact 1096×170 /
  grid 1080×158，适配后缩放 **0.279 → 0.303 → 0.432**，即网格模式下卡片实际
  大 **55%**；点击任意模式都会把手动偏移清零（offsets 6 → 0）；切换后仍可拖动、
  可重置、可再整理；无页面报错。单测覆盖：紧凑行距更小、网格横向更窄且把宽行折成
  多行、**网格无重叠卡片**、连线数量不变、偏移在网格模式同样生效。

### 节点级拖动（任务管理图：手动摆放卡片）

- **交互**：直接拖动画布上的卡片即可移动。默认**连同其子树一起走**（拖动主代理
  就是整棵树平移），按住 **Alt/Option 只移动该卡片**；`Alt` 的语义写进代码注释，
  手柄光标为 `grab`/拖动态 `grabbing`。
- **实现**：手动位置以「相对自动布局的偏移」保存（`NodeOffsets`），自动布局仍是
  底座——`layoutTasksViewModel(model, offsets)` 在放置之后应用偏移，**连线与内容
  包围盒都按拖动后的真实位置重算**；偏移按树根缓存（与相机同族、切模式/重开标签
  不丢），并提供 **「⟲ 重置布局」** 回到自动布局（无手动布局时不显示该按钮）。
- **不误触**：拖动位移超过阈值后，松手不会触发导航；轻点（未移动）仍照常进入该
  子会话。画布平移、缩放、适配都不受影响；「适配」会把拖到负坐标的内容一并框进来
  （`minX/minY` 参与计算）。
- **实测**：叶子子代理拖动 → 偏移 1 条（只动自己）；拖主代理 → 偏移 6 条（整棵
  子树）；Alt + 拖主代理 → 1 条；拖动后连线同步变化；点「重置布局」逐字节回到
  自动位置且按钮消失；轻点仍能进入子会话；无页面报错。纯函数单测覆盖偏移应用、
  子树/单节点语义、增量基于手势起点、包围盒越界扩张与重置。

### 工作流图相机策略修复（手动拖动总被踩回默认区域）

- **故障**：`fit()` 原先在**每次模型/布局变化**时无条件执行——执行期的活动
  轮询（live 2s、workflow runs 5s、会话 feed）不断重建视图模型与布局，于是
  手动拖动的位置每两秒被重新适配踩回默认区域，部分节点长期在视口外；`fit()`
  还会清掉"用户已手动调整"标记，让自动适配永远赢。
- **修法**：新树（root id 变化）才自动适配并清除手动标记；**同一棵树**
  只在视图仍处自动态时适配（`!userAdjustedRef`），用户一旦拖动/缩放就不再
  抢占；ResizeObserver 与拖拽中同样不抢；「适配」按钮保持显式复位语义。
- **实测**：拖动 `-220,-120` 后触发刷新 + 跨两轮轮询（覆盖 live 与 workflow
  两个轮询窗），transform 逐字节不变；「适配」可复位。
- **相机跨模式/跨重挂粘滞**：图/树切换会重挂画布组件，原先相机随之丢失。
  现按**树根**缓存相机（含"用户已接管"标记，容量 12、最旧淘汰）：切回图或
  离开会话再回来重开任务管理，都恢复到你上次的取景；未见过的树仍走自动适配。
  实测：拖动后 `translate(-51.5,217)` → 树→图 保持 → 切走工作区/会话再切回并
  重开任务管理仍为 `translate(8.5,257)`（与拖动值逐字节一致，而全新适配为
  `translate(208.5,347)`）。

### macOS 桌面拖拽域修复（上游 v0.22.1 / issue #772）

- **故障**：宿主规则 `html[data-platform=darwin] body > :not(#root)
  { -webkit-app-region: no-drag }` 命中本插件**直挂 body** 的面板宿主；而
  app-region **无视 pointer-events**，视口尺寸的宿主层把整条标题栏拖拽带
  抵消——桌面壳上「窗口拖一次就失效、双击标题栏缩放失效」。
- **修法**（照上游）：面板宿主与放大视图（mermaid modal，同样 portal 到
  body 的铺满层）用中性值 `-webkit-app-region: initial !important` 退出
  blanket；宿主的**子层保持 `no-drag`**（我们的按钮在标题栏条上按下不会
  变成拖窗，延续 #103/#111 的既有约束）；交互弹层（划选弹层/浮动窗/锚定
  气泡）**不加** `initial`，否则按下会变拖窗。
- **实测（计算样式 + CSSOM）**：宿主 `none` / 子层 `no-drag`；模拟
  `data-platform=darwin` 后普通 body 子元素仍为 `no-drag`（blanket 未被
  破坏），证明只退出了我们这两层。产物级断言已加入 `smoke`（中性规则
  ≥2 处 + 子层 no-drag 在位）。

### 工作流 run 入图（上游 v0.22.0 对应项）

- **宿主折叠**：新增 `src/subagent-workflow.ts`（纯函数）从 `tool-workflow/*`
  事件家族折叠 run：`run-start{runId,name}` / `agent-start{seq,label,phase?,childId}`
  / `agent-end{seq,outcome}` / `run-end{stopReason}`。相位按**组内最小 seq**
  排序（工作流定义序），无相位成员排尾；`agent-end` 的 outcome 按 seq 归位。

- **入图**：`buildTasksViewModel` 新增 `run` / `phase` / `member` 三种节点——

### 工作流图交互修复（实机发现的三个缺陷）

- **画布只显示一小块**：图模式仍复用 `overflow-y:auto` 的滚动容器，其中
  `flex:1` 无效 → 画布塌缩成内容高度。现图模式切换为弹性列
  （`.subagentBodyGraph`，不滚动），画布撑满面板（实测 1019px / 面板 1029px）。
- **节点点不动、＋/−/适配没反应**（同一根因）：容器上调用
  `setPointerCapture` 会把随后的 `click` 重定向到容器，节点 `<g>` 与控制条
  按钮的 onClick 都不触发。现改为拖拽期间挂 `window` 指针监听，不再捕获；
  控制条另行 `stopPropagation` 与拖拽解耦。实测：缩放/平移/适配/节点导航
  全部生效（点子代理 → 面包屑切到该子会话）。
- **尺寸变化不重排**：新增 `ResizeObserver` 自动适配（用户手动平移/缩放后
  不再抢视图，点「适配」可复位自动模式）。

### 浅色主题可读性修复（实机发现的 token 错误）

- 工作流图首版用了**宿主不存在的 token**（`--dsw-alias-bg-primary` /
  `bg-secondary` / `border-strong` / `border-subtle` / `state-running-primary`）：
  `var()` 解析失败时 SVG `fill` 回退为**默认黑色**，浅色主题下变成黑底黑字、
  完全不可读。
- 现改用宿主 `body` / `body[data-ds-dark-theme]` 上**实际定义**且本仓库既有
  规则验证过的 token：卡片改「透明底 + `border-l2` 描边」，分段用分隔线，
  底条用 `interactive-bg-hover`，运行点/当前描边用 `interactive-bg-hover-accent`，
  文字用 `label-primary/secondary/tertiary`。
- **双主题实测（计算样式取值）**：深色 卡底透明 / 描边 `rgba(255,255,255,.24)` /
  文字 `rgb(249,250,251)`；浅色 卡底透明 / 描边 `rgba(38,49,72,.14)` /
  文字 `rgb(15,17,21)`——两主题均清晰可读。

### 团队 tab 状态机补全（实机发现的 UX 缺口）

- 非团队会话（从未用团队工具）的投影读取会**正常完成但不发布 `agentTeam`
  值**——旧逻辑会停在「正在读取团队状态…」永转圈。现派生为终态
  `not-team` → 空态「当前会话不是团队会话」，不再无限等待。
- `projection-missing`（宿主 <0.1.7）判定收窄：仅当快照完全没有投影 store
  时呈现；`idle/loading` 一律视为读取中。

### 发布期修正：产物烘焙版本必须 = package.json（新增门禁）
