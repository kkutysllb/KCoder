# dsh-coding-sidebar 1.0.21

> 0.1.5 门（`sidebarRight.openResource` 文件打开拦截）延迟装配修复。

## 背景

dev 现场：点消息里编辑过的文件（工具行的文件链接）→ 打开的是**原生右侧栏**
（而原生外壳被产品侧压制 → 一片空白），不是本插件的编辑器预览。

根因：0.1.5 起 ui-chat 的文件打开走 `ctx.sidebarRight.openResource(...)`
（alpha.2 的 `apply.ts` 仍是这条），而本插件装这道门用的是**一次性
`ctx.get('sidebarRight')` 探针**——该服务由上游 web patch 组合提供、不在
本插件的 inject 清单里，客户端模块激活顺序一旦让探针先跑，服务尚未就绪 →
**这道门永久未装配**，文件打开落回原生通道。alpha.1 时代没暴露是因为那时
ui-chat 走 `remote.session.openWorkspacePath`，而 `remote.session` 在 inject
清单里、天然等到就绪。

## 变更

`registerOpenPathInterception` 的第三道门改用 `ctx.inject(['sidebarRight'], cb)`
延迟装配：服务就绪即装（已在则同步回调），载具永不提供时回调不触发、门保持
未装（与旧降级面一致，且不阻塞插件激活——file-review 曾因 inject 缺席的
服务而 pending，这类教训不重演）。清理走 `Fiber.dispose()`。

## 验证

typecheck / build / test / smoke / check:artifacts 全过。
