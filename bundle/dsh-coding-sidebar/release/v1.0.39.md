# dsh-coding-sidebar 1.0.39

> 变更审查手势**认领进自家侧边栏**：点交付物卡的「查看变更」原本落到被压制的
> 原生右栏，得到一条空白列、文件从不出现；现在由插件接手，打开的文件进自家
> 编辑器，与内建审查页签「检视」按钮同一落点。

## 变更

### 故障（现场 2026-10-05）

- 上游 ui-deliverables 的变更文件卡把「查看变更」交给**原生右栏**：
  `ctx.sidebarRight.openResource('dsh-resource://changes-review/session/<id>/<seq>/<turn>',
  { params: { index } })`。
- 本插件包裹的三道文件门（`openPath` / `wrapRemoteOpenPath` / `openResource`）
  只认领 `file` 作用域（`fileTargetOfAddress` 只匹配 `dsh-resource://file/…`），
  这条地址没有任何门认领，于是**穿透到原生右栏**——而原生右栏面板是 KCoder
  有意压制的（产品铁律 1，`docs/ARCHITECTURE.md` §12）：用户点交付物文件，
  得到一条**空白列**，文件本身从不出现。
- 与 2026-09-19 原生 browser tab 那次同构（地址族落进被压制的原生面板），
  处置也同构：**插件认领该手势**。认领放插件而不是改宿主，守的是铁律 2：
  上游版本适配活在插件里、以插件版本发布。

### 地址语法（新增 `src/client/review-address.ts`）

- **零依赖**（不 import React / ui-primitives / 运行时）：语法与摘要取数可从
  纯 node 测试运行时单测，也可在客户端运行时之外引用。
- `parseChangesReviewAddress()` 解码
  `dsh-resource://changes-review/session/<id>/<seq>/<turn>`：
  - 同时接受 **QiLin 通道**的 scheme 改名 `qilin-resource://changes-review/…`
    （与 `FILE_ADDRESS_PREFIX` 同一改名规则），两条通道都不静默拒绝；
  - 容住 builder 的怪癖：`turn` 被 builder 无守卫插值，手拼地址可能写出字面量
    `undefined`——**拒绝**而非带着走；`seq` 必须是非负安全整数；Session id 必须
    非空且百分号转义合法（`decodeURIComponent` 抛 `URIError` ⇒ 整条拒绝）；
  - `turn` 是展示性字段，缺席合法。
- `reviewIndexFromOptions()` 读 `options.params.index`（变更文件卡传的是被点
  行的**原始下标**），非负安全整数之外一律视为未指定。
- `reviewedPath()` 从宿主变更摘要里挑该打开的文件：宿主应答是**不受信输入**，
  结构逐项校验（`files` 非数组、行缺 `path`、空 `path` ⇒ 拒开假路径）；
  **下标越界退回首文件**，与内建审查页签自己的默认导航一致。
- `changesSummaryUrl()` 产出宿主摘要路由，与运行时 `changesSummaryUrl` 逐字
  同形态的**文档相对**写法（app 路由按契约即文档相对）。

### 认领点（`src/client/openpath-intercept.ts`）

- `openResource` 门新增**第二族地址**的认领，判定先于 file 家族（审查地址同用
  resource scheme 但不指文件，file 家族只会拒绝它）。
- `OpenPathInterceptDeps` 增可选 `openReview(coordinates, index)`；不接线时
  该族地址照旧穿透，与其它未认领地址一致。
- 四种情形一律穿透到原方法：**未接线** / **认领方返回 false** / **点名
  `options.kind`**（调用方在有意指名右栏页面，改道等于静默无视其请求）/
  **takeover 总开关关闭**。file 家族三条既有行为**零变化**。

### 落点（`src/client/intercept.tsx`）

- `openReviewInSidebar()`：fetch `api/changes.summary?sessionId=…&seq=…` → 按
  `index` 取该行文件 → **进自家编辑器**——与内建审查页签逐文件「检视」按钮
  同一落点（`fileAddressFor(sessionId, cwd, file.path)`，`file` 作用域在这里
  被认领），跨工作区读取作用域随页签带。
- **认领刻意永不穿透**：该地址若放行，唯一去处是被压制的原生面板，用户什么
  都看不到。摘要读不到（宿主已不服务 / 传输失败 / 无可用路径）时**兜底**落到
  该会话的编辑器页签并展开面板——这个 openTab 带不出内容，面板展开由本函数
  上行完成，并按契约就地标注 `// open-tab:type-only`。
- `openResource` 是同步漏斗，摘要是**发射后不管**：fetch 完成后页签才开。

## 兼容性说明

- 无 peer/契约变化；`dsh` 声明、`cordis.patch.yml`、服务面与 agent 工具均未动。
- file 作用域三条门的原有行为不变；`options.kind` 点名与 takeover 关闭的
  穿透语义不变。
- 宿主 `openResource` 包裹仍是原型方法捕获 + 重挂载自愈，HMR 安全。
